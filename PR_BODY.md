## What / why

Fixes #7642 (EP-1, docs-fix per the maintainer-approved Decision on the issue).

`texra.model.retry.maxAttempts` promised "Set to 0 for no automatic retries",
but `ModelInvocationNode` skips the flow retry for Anthropic/OpenAI/OpenAIResponse
(`isAutoRetryManagedByProvider → true`), and the handler constructors never
pass `maxRetries` to the SDK — so the SDK's own default of 2 retries is the
sole owner for those three providers. Only Google and OpenRouter 429/408 (plus
background transients) actually honor this setting. The description was false
for the three most-used providers.

Per the issue's Decision (**docs-fix now; no ownership flip**):

1. Rewrote the `texra.model.retry.maxAttempts` description in the
   `coreSettings.ts` catalog (`src/shared/schemas/coreSettings.ts`) to say
   retries are flow-managed only for Google/OpenRouter 429-408/background
   transients, and that Anthropic/OpenAI/OpenAIResponse retries are
   provider-managed by their SDKs (default 2) and unaffected by this setting.
2. `packages/extension/package.json` is code-generated from that catalog via
   `npm run sync:package-contributes` (confirmed: `scripts/sync-package-contributes.mjs`
   regenerates `contributes.configuration` from
   `out/packages/extension/src/schemas/texraSettings.js`, which is built from
   `coreSettings.ts`) — ran the sync instead of hand-editing package.json, so
   the two stay mechanically in sync (verified via `check:package-contributes`).
3. Aligned the `RetryState.ts:25` `getConfig` fallback from the stale literal
   `1` to `DEFAULT_CORE_SETTINGS.model.retry.maxAttempts` (the canonical `0`),
   importing it from `@shared/schemas/coreSettings` (existing pattern, see
   `ModelFactory.ts`).
4. Added one `RetryState.vitest.ts` case pinning "config unset → `Node.maxRetries`
   equals `1 + DEFAULT_CORE_SETTINGS.model.retry.maxAttempts`".

**Rejected trap (honored):** did NOT pass `maxRetries` into the SDK
constructors and did NOT flip the owner-selector — owner-selector and count
must move together, and unifying ownership is deferred. This PR is docs +
fallback-alignment only; behavior for every provider is unchanged.
