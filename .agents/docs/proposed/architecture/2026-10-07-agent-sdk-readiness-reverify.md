## What moved since the 2026-10-04 pass

The last pass closed by predicting that "re-running this audit as a routine will
again add no signal **until the harness program moves**." It moved. The delta is
structural, not behavioural, and it is exactly the harness-program progress that
pass was waiting on:

1. **The harness package rename landed.** The SDK package is now
   `packages/harness` (`@texra-ai/harness`); `packages/agent` is gone and no
   `@texra-ai/agent` import remains in source (only design-doc prose still names
   it). This resolves **durable-harness Q5 (package name) in the tree** — the
   proposal was `@texra-ai/harness` and that is now the live name. Two proposal
   docs trail the tree and need an owner to reconcile their status: 
   `2026-10-02-durable-harness.md` still lists Q5 as "open" (:15, :450), and
   `2026-10-02-harness-package-split.md` is still `status: proposed` though its
   package now exists. (Doc-lifecycle drift, not a code finding.)
2. **Persistent sessions + `session.resume` + an approval handler landed**
   (#13867). `ApprovalHandler` is now a root public type (`index.ts:30`) and
   `Session.resume` is part of the `Session` contract (`effect/sessions.ts`).
   This is the durable-harness "extend" surface (that note's H4) reaching the
   public boundary, as the pivot intended — intended surface, not drift.
3. **`effect/runtime.ts` is gone.** The last pass cited `Composition` from
   `./effect/runtime.js` and named that file as the sink-less composition root.
   The composition moved into `effect/sessions.ts` (`index.ts:26` now sources
   `Composition` there); `packages/harness/src/effect/` is now

4. **The run loop was decomposed again.** `loop/rounds.ts` and
   `loop/reflection.ts` are both gone; `packages/harness/src/agent/runtime/loop/`
   is now `{hooks,modelSwitch,rows,runProgram,step,toolGuard,toolUse,toolUseDispatch}.ts`.
   Still one `Effect` per run appending one history — each file is an
   Effect-native slice of that one program, not an added indirection tier (the
   agent-core audit traced the full spine and found no forwarding layer).
5. **`host-agent-import-baseline.json` was retired** (emptied under ruling SQ2).
   The 2026-10-04 "Genuinely open" item "shrink the host-agent-import frozen
   list" is **resolved by retirement**: that file counted only host `@agent/*`
   edges, now subsumed by `harness-deep-import-baseline.json`, and the SDK entry

6. **A generated, diff-gated public-surface inventory now exists.**
   `config/api-reports/harness.api.md` (plus `.node`, `.plugins`, `.schemas`,

   `scripts/check-core-quality.mjs --update` and declares, at its head, "**a diff

   Tier-1 manifest's *enumeration* half — the surface is now machine-enumerated
   and diff-gated — leaving only the *ratification* half (which to keep or seal)

`config/ratchets/refuted-candidates.json` is unchanged in substance: the same

## Verdict (unchanged)

The codebase is still well-aligned, and this audit remains a standing program,
not a gap. **No autonomous refactor is warranted from this charter.** Four
read-only audits this pass — one each over the agent core, the model handler,
the logger, and the SDK public surface, all against the current `packages/harness`
tree — found **no wrapper layer that only forwards, no second run-history
writer, no services-bag, no re-export shim, no redundant interface-over-one-impl**.
Every safe candidate in these areas is already filed, already landed, or already
recorded as refused with a ruling. The one net-new, first-sighting item is a
two-line logging-consistency fix (§New.2), documented rather than applied.

## The four asks, re-mapped to the current pin

1. **Identify the areas.** Re-confirmed on the renamed tree:
   - **Agent core:** `packages/harness/src/agent/core/` (`definition/`, `state/`,
     `tools/`); the run program `@agent/runtime/loop/toolUse.ts` over the run
     history; the loop now decomposed across
     `loop/{runProgram,step,toolUseDispatch,toolGuard,hooks,modelSwitch,rows}.ts`;
     the model call is `@agent/runtime/ModelInvoker.ts` (with `helperModel.ts`
     and `run/compaction.ts` invoking the bound `Model` directly — deliberate
     exceptions, not a second handler). The spine is five layers — `runAgent` →
     `executeAgent` → `launchRun` → `runToolUse` → `ModelInvoker` — each adding a
     distinct responsibility; none is a pass-through (shared retry SSOT is
     `run/invocation.ts` `runInvocation` with three distinct `InvocationDriver`
     callers).
   - **Model handler:** provider calls are reached only through the
     `packages/llm` (`@texra-ai/llm`) `Model` bound by
     `runtime/run/modelBinding.ts`; the published/Node split (harness `bindModel`
     knows hosts, `@texra-ai/llm/node` `bindModel` knows wire protocols) is the
     SDK boundary, not two layers doing one job. Deliberate exceptions outside
     that route unchanged (audio transcription builds `OpenAI` directly; `codex`
     and `claude_code` tools load their own SDKs; the settings-view consent probe
     acquires a VS Code `Model`).
   - **Logger:** `packages/harness/src/logger/`
     (`effectLog.ts`, `logSink.ts`, `effectDiagnostics.ts`, `formatLogData.ts`,
     `redaction.ts`). One authority; `LogEntry` **is** Effect's own structured
     shape (`ReturnType<typeof Logger.formatStructured.log>`), so this is not a
     hand-rolled logger; `effectDiagnosticsLayer` wires `Logger.make` onto
     `writeLogEntry`; `withLogChannel` is a 3-line annotate-logs combinator.
   - **SDK surface:** `packages/harness` (`@texra-ai/harness`) — `index.ts`,
     `node.ts`, `schemas.ts`, `plugins.ts`, `effect/`; now pinned by
     `config/api-reports/`.

2. **Audit for unnecessary abstraction.** Done, four ways; all clean.
   - **Agent core:** no forwarding layer. The only "shallow"/"pass-through"
     items (`executeAgent.ts`, `FollowUps.ts`, `runRegistry.ts`,
     `nativeSubagentStrategy.ts`, `runtime/index.ts`, `core/tools/ToolTypes.ts`,
     `RunHandle.ts`) are already recorded and frozen in
     `config/ratchets/core-quality/{pass-through,shallow-modules}.json` — accepted
     debt, not new. `ModelRetryGate`→`Schedule` stays refuted.
   - **Model handler:** already heavily de-duplicated; no shim, no
     interface-over-one-impl (`LanguageModelPort` has two real impls; `judgedModel`
     threads billing into one error map rather than duplicating `mapError` across
     protocols). The only discussable item is the **documented** `BoundModel`
     denormalized mirror fields (`modelBinding.ts:76-81`) — intentional so the
     media pipeline and retry gate don't re-reach the config/route.
   - **Logger:** one minor consistency finding (§New.2); otherwise a model
     citizen. The sink→Layer conversion remains the one structural item (§Open).
   - **SDK surface:** center (Sessions/Session/Run + tagged errors + `defineTool`,
     pure-Effect, no in-package `runPromise`) is minimal and clean; redundancy is
     at the edges (`SettingHost`, the `MapToolRegistry`/`IToolRegistry` registry
     plumbing an embedder on the `StartInput.tools`/`defineTool` path never
     constructs) — the same shed candidates the last pass named, carried into the
     manifest re-scope (§Open).

3. **Plan API-surface simplification.** Still the durable-harness "extend" half
   (`2026-10-02-durable-harness.md` H4 — `Plugin`, `Sessions.layer({ plugins })`,
   `Plugins.contribute`, `Session.resume`, now partly landed per §What-moved.2)
   plus the frozen-list shrink, **not** ratification of the 2026-09-10
   static-export manifest. The SDK speaks pure Effect end-to-end; the Promise
   boundary is deliberately gone.

4. **Design subagent boundaries.** Already first-class, re-confirmed unchanged:
   (a) native subagents via `executeAgent` with an owned `RunId`; (b) the
   workflow-script run plus its `agent()` grandchildren; (c) the agent-CLI
   children (`claude_code`, `codex`) through `startDetachedChildRunLoop` with
   provider-specific `ChildRunStrategy`. The non-candidates
   (reflection/round output extraction, `compileCheck`, `LatexDiffManager`) still
   have no independent run or model lifecycle, so reifying one buys nothing. No
   boundary change is warranted.

## New since the 2026-10-04 pass

1. **The Tier-1 manifest enumeration is now automated and diff-gated; only
   ratification is left, and the 2026-09-10 draft is staler than ever.**
   `config/api-reports/harness.api.md` (88 root exports, generated and
   diff-checked) is the enumeration the 2026-09-10 proposal tried to maintain by
   hand. That hand-written draft is now stale on three counts: it is enumerated
   against the deleted `packages/agent/src`, it names a type that no longer
   exists in the package (`ToolHost`), and it omits the very extend surface the
   pivot is built on (`Plugin`, `Composition`, and now `ApprovalHandler`/resume).
   The owner action owed is unchanged: **re-scope the manifest around the harness
   SDK rather than ratify the old static list** — and the generated report now
   gives that re-scope a concrete, enforced inventory to prune from.

2. **Logging-consistency finding (first sighting; documented, not applied).**
   `packages/harness/src/shared/schemas/agentPresets.ts:37` and `:49` —
   `parseAgentModePresets` runs in the VS Code-free harness core across all three
   hosts but emits malformed-preset warnings through raw `console.warn` instead
   of the single host sink, so they bypass channel attribution, redaction, and
   level routing, and under the CLI's `silentLogSink`/NDJSON leak outside the
   structured stream. The established fiber-less-sync pattern is
   `writeLogLine('WARN', channel, message)` (as in
   `utils/system/platformPaths.ts:46`). **Not applied this pass**: that pattern
   lives in `utils/`, whereas `agentPresets.ts` is under `shared/schemas/` (wire
   contracts), so adding a `@logger` import there is a layering decision that must
   first be checked against the `dependencyDirection` ratchet and the
   `shared/schemas` deep-import rule — an owner call, not an autonomous edit.
   First pass to flag it; apply only on a second sighting or an owner's say-so.

(package rename, persistent sessions + resume + approval handler, the
`config/api-reports/` surface gate, the retired host-agent-import baseline), and

trailing proposal-doc statuses. Re-running this audit as a routine will again add
