# Model access after split step M4: what the sweep left for a design call

Date: 2026-10-03
Status: proposed
Origin: the simplification sweep over model access after split step M4
(#13644 moved `src/auth` and the model catalog and routing into
`@texra-ai/llm`), #13650 (`fetch` accepts a `Request`) and #13667 (the
`API_PROVIDERS` aliases dropped). The sweep's batched PR removed what M4 had
made unnecessary: the signed-in probe registry in `src/model/subscriptionAccess.ts`,
a second copy of `acceptedEfforts`, a one-function file, and dead or alias
type exports in the `.` entry. M4 left no forwarding module, re-export or old
subpath behind (checked by `rg` for `@auth/`, `@texra-ai/llm/<subpath>` and the
pre-move paths). The `llm` package reads no settings, and nothing under
`models/` or `providers/` imports a Node module. The findings below are the
ones the sweep did not implement. Each one changes a persisted format, lies
in a file another lane owns, or needs a decision about the `.` entry.

## 1. Two compatibility keys name one conversation format

`ModelCompatibilityKey` (`src/shared/schemas/runSnapshotState.ts:157`) has
both `OpenAIResponse` and `OpenAI`. They bind the same protocol:
`PROTOCOL_BY_KEY` (`src/agent/runtime/run/modelBinding.ts:132`) maps both
to `openai-responses`. The OpenAI provider plugin names `OpenAI`
(`packages/llm/src/providers/providerPlugins.ts:109`), but
`routeCompatibilityKey` (`src/agent/runtime/modelRoutes.ts:448`) overrides it
with `OpenAIResponse` for every OpenAI model that is not `openRouterOnly`.
A direct route stamps `OpenAI` only for a model that is both
`openRouterOnly` and `requiresResponsesAPI`. The current llm-zoo catalog has
no such OpenAI model: both `openRouterOnly` OpenAI entries route through
OpenRouter. So `OpenAI` is a second name for a format that is never written
in practice. `resolveModelRoute` reads only `OpenAIResponse` (`:370`).

Proposal: give the OpenAI plugin `compatibilityKey: 'OpenAIResponse'`, delete
`OpenAI` from `ProviderCompatibilityKey`, `MODEL_COMPATIBILITY_KEYS` and
`PROTOCOL_BY_KEY`, and drop the OpenAI branch of `routeCompatibilityKey`. The
default arm then reads the plugin, as it does for every other provider.
Net: one enum member, one map entry and one branch gone, about −8 lines.

Not done here: the key is persisted on run snapshots, so removing a member
is a store-format change. Under the 1.0 clean-state rule that is allowed,
but it belongs with the next format bump rather than in a sweep.

## 2. The subscription endpoints live on the host side of the move

`resolveRouteEndpoint` (`packages/llm/src/models/routeEndpoint.ts`) calls
itself "the one owner of endpoint precedence", but it covers only the
`openrouter` and `api-key` routes. The two subscription routes take their
endpoints elsewhere:

- `CODEX_BACKEND_BASE_URL` is exported from `./node`
  (`packages/llm/src/oauth/codex/codexConstants.ts:68`). Its one production
  importer is `src/agent/runtime/modelRoutes.ts:178`.
- `XAI_SUBSCRIPTION_ENDPOINT` (`src/agent/runtime/modelRoutes.ts:53`) repeats
  the xAI plugin's `baseUrl` (`providerPlugins.ts:138`) as a host constant.

Proposal: widen `resolveRouteEndpoint` to the two subscription route kinds.
They come before the per-model `baseUrl`, because a subscription token is
accepted only at its own surface. The xAI arm reads the plugin's default
endpoint. Then delete `XAI_SUBSCRIPTION_ENDPOINT` and drop
`CODEX_BACKEND_BASE_URL` from `./node`. The constant moves to a
browser-safe module, since `codexConstants.ts` imports nothing. That
removes one `./node` export and one host constant, and every route's
endpoint comes from one function.

Not done here: the subscription rows in `modelRoutes.ts` are where the
binding reads the endpoint. Moving it changes `SubscriptionSession`'s shape,
which is more than a sweep edit.

## 3. Routing predicates restate `ModelConfig` fields for test fixtures

`KimiSubscriptionModelFields` (`packages/llm/src/models/kimiCodeRetryGate.ts:19`)
and `OpenRouterRoutingConfig` with `ModelRoutingConfig`
(`packages/llm/src/models/openRouterRouting.ts:8`, `:21`) are hand-written
copies of four `ModelConfig` fields. They type `provider` as `string`, not
`ModelProvider`, so that a test fixture can pass partial objects. Every
production caller passes a `ModelConfig` or a `Pick` of it. The only
partial callers are `src/test-kernel/model/KimiSubscriptionRouting.vitest.ts`
and `src/test-kernel/model/OpenRouterRouting.vitest.ts`.

Proposal: type the predicates over `Pick<ModelConfig, 'provider' |
'kimiSubscription' | 'baseUrl' | 'openRouterOnly' | 'requiresResponsesAPI'>`
and delete the three restated types. The two suites then build their
fixtures from catalog entries, or spell `ModelProvider` members. This
tightens the types (`provider` gains its enum) and removes three
declarations.

Not done here: it rewrites two suites' fixtures, and the tightening is
worth doing only together with that rewrite.

## 4. `export *` hides the `.` entry's dead exports from the ratchet

`packages/llm/src/index.ts` publishes whole files with `export *`, and knip
counts every name an entry publishes as used. So the dead-export ratchet
cannot see a symbol that nothing outside the package imports. That is how
the sweep found `ApiKeyOrigin` (a bare alias of `CredentialOrigin`) and three
`export`ed types with no reader outside their own file. These names still
reach `.` with no production importer outside the package, only a test or a
sibling module: `KimiSubscriptionModelFields`, `KIMI_CODE_BASE_URL`,
`FAST_FIRST_RESPONSE_HINT`, `isOpenRouterRoutingUnsupported`,
`shouldRouteModelThroughOpenRouter`, and the upload and background types of
`turn.ts` (`FileUpload`, `UnreleasedUpload`, `BackgroundSubmission`,
`ObservationPolicySchema`, `FILE_UPLOAD_LIFETIME_SECONDS`), which the
protocols read.

Proposal: either list the published names in `index.ts` (as `node.ts`
already does), or set knip's `includeEntryExports` for the `packages/llm`
workspace and baseline what it reports. Either way, the README's sentence
"the two entries, whose published names are contract" is then enforced
rather than assumed. The explicit list is the cleaner of the two: it is the
documented public surface the "no convenience barrels" rule asks for.

Not done here: it decides what the `.` contract is, which belongs to the
owner, and the explicit list touches every consumer's view of the entry at
once.

## Rejected during the sweep

- **Collapsing `src/model/codingPlanSubscriptions.ts` into the llm
  catalog.** The host file adds only the two preference toggles and the
  usage-setting lookup over the llm descriptor, which are settings the
  package must not read. That is the split the design doc asks for.
- **Folding `src/model/modelRoute.ts` into `modelRoutes.ts`.**
  `readRouteFacts` has two production readers (the picker and the binding),
  and the design doc keeps it in the harness beside them.
- **`availabilityStatus(kind)` in `computeModelOptions.ts`.** It is a
  trivial factory, but it has eight callers and is not M4 residue. Inlining
  it is churn without an element worth the review.
- **`isCodexSubscriptionEligible` and `bindEditorModel` single-caller
  helpers.** Each names a decision its caller would otherwise inline as an
  unexplained conjunction or an 80-line arm. They are named stages, not
  pass-throughs.
