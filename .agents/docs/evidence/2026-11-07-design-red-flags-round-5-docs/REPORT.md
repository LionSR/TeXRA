Read at `main` `c9ceb23` (#14826), after #14820 (CLI runtime and commands) and
#14822 (usage telemetry). Scope: every page of `docs/guide/` (including
`workflows/` and the unpublished `desktop.md`), the public root docs in

Each claim was checked against the code: CLI commands, flags and help against

## Top findings

1. **Resume rules missing from the CLI page.** A one-shot `texra run` that
   ended cannot be resumed (exit 2, pointing at `history show` or
   `resume --fork`); one stopped mid-turn resumes to finish the turn; a resumed
   task keeps its launch approval policy; forking needs a terminal and a
   document task cannot be forked. Added to `texra-cli.md`.
2. **Approval policy precedence.** `--approval-policy`, `TEXRA_APPROVAL_POLICY`
   and `--no-input` only narrow the stored policy, which is read from the user
   files and never the project file. `yolo` still yields to a stored `never`.
   The CLI page and `ConfigPrecedenceStack.vue` presented them as overrides and
   left out the user-config tier (`~/.texra/v1/global-storage/config.json`).
3. **History outcome vocabulary.** The CLI page listed
   `completed`/`interrupted`/`error`; the store reports
   `completed`/`cancelled`/`failed`/`null` plus `resumable`, and the page
   contradicted its own NDJSON section.
4. **The SDK storage model (`docs/api/durable-protocol.md`, `index.md`).**
   Both described per-aggregate ownership claims and two errors removed in
   #14776. One process holds a project store exclusively; a second open is
   refused. Rewritten, with eight names the packages no longer export removed
   and wrong subpath links fixed.
5. **Settings pages.** `configuration.md` described a **Tools** page that no
   longer exists; the pages are Models, Agents, Memory, Plugins, LaTeX and
   General, with approval under General → Approval. Pages across the guide used
   old labels (Execute, Run agent, Sessions view, "in this run",
   "Diff consecutive rounds", a collapsible LaTeXDiffs section); all now match
   the UI (Start task, Tasks, "in this task", "Diff consecutive revisions",
   the **LaTeXDiffs…** sheet).
6. **Run folder layout.** `quick-start.md`, `OutputArtifactsTree.vue` and
   `StorageLifecycleFlow.vue` put logs and diff PDFs inside `r0/` and named
   outputs `output.tex`. Each `r{n}/` holds the revised document (input
   filename) and `output.xml`; diffs sit under `diff/r{n}/`, compile logs under
   `compile/`. Pack and Archive copy a run; they do not move it.
7. **Usage telemetry.** The landing-page privacy FAQ did not mention it; the
   configuration page listed fields the code does not send. Both corrected.
8. **Desktop page.** It claimed agent and model settings stay per host; every
   setting is shared through the stores under `~/.texra`. The updater text
   described a planned auto-updater; the code checks daily and only shows a
   download link.
9. **Agents.** Team membership, `assistant` in the Starter set, the
   `paper2poster`, `transcribe_audio`, `merge` and `ocr` descriptions, agent
   name rules, and the "strict XML" warning (TeXRA closes an unclosed
   `<document>` itself) were wrong on several pages.
10. **Code review.** The scaffold uses `review@v2`, which needs CLI 0.41 or
    newer; a custom-prompt snippet carried an `if:` that only this repo's own
    workflow satisfies.
11. **No real people.** A Zotero example named an identifiable author; replaced
    with a topic.

#### Code-is-wrong

1. **Telemetry opt-out key printed without its namespace.** The first-run notice (`packages/texra/src/telemetry/telemetryNotice.ts:13`) and the `texra doctor` hint (`packages/cli/src/runtime/doctor.ts:351`) both say `"telemetry.enabled": false` in `~/.texra/v1/global-storage/config.json`. Stored keys carry the `texra.` namespace (`jsonConfigProvider.ts:78`), so that line has no effect. I checked it: with `{"telemetry.enabled":false}` doctor still reports "Usage logging: On", and with `{"texra.telemetry.enabled":false}` it reports "Off". The doc's `texra.telemetry.enabled` is correct. Both strings use `TELEMETRY_ENABLED_SETTING.key` and should use the stored key.
2. **Stale code comment.** `packages/cli/src/schemas/cliOutput.ts:258-270` says `CliRunStatus` (completed/interrupted/error) is the "CLI NDJSON history status". History records carry the raw `outcome` (completed/cancelled/failed/null). Today it is used only for headless text status lines.
3. **"paper" for the user's project in CLI help**: root help example `texra clone <project> ./paper` (`packages/cli/src/commands/root.ts:122`), clone help example and the non-empty-destination error `texra clone 0123… ./paper` (`packages/cli/src/commands/clone.ts:97,220`). An Overleaf project is the user's project, so `./project` (as the guide uses) fits. `texra plugin --help` example `--plugin paper` (`commands/plugin.ts:424`) is a plugin name, so it's borderline.
4. Minor help drift: `texra setup` description "(ChatGPT or an API key first)" (`commands/setup.ts`) leaves out Grok, which the Connect panel and `texra auth grok` offer. `team run --help` RUN MODE "rich TUI: use `texra chat` and ask the team lead" (`commands/team.ts`) leaves out picking the team in `/agent`, which is what scopes delegation.
5. `[agentRegistry] Loaded 40 agents in NNms` prints on stderr for every command, even `models enable`/`config show` without `--verbose` (noise, not a doc issue).
