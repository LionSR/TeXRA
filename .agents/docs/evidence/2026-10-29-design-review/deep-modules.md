## 1. Verdict

pi-durable has the deepest core: `Conversation.submit/commit/watch` and a four-member `Submission` are general primitives over 28,841 lines, and defaults carry the configuration. TeXRA has the deepest unit a user writes against: a six-member `Run`, a one-argument tool body and a `RunEnd` that already holds the answer. Its weaknesses are a request multiplexer whose answers are not typed per kind, the same launch options spelled three ways, and two concepts an embedder must supply although a default could. DeepSeek's SDK is the narrowest of all (two classes, 9 members), but it buys that by moving every extension to Cordis plugins composed in YAML in a subprocess, so the real interface is the deployment.

Grades: **TeXRA B+** (deep `Run`/tool contract; request answers untyped, option vocabulary duplicated). **pi B** (durable A-, coding-agent C: a 77-method `AgentSession` and an 11-method replacement interface). **DeepSeek B-** (excellent SDK depth; a custom tool needs three files in two languages, and `Agent` exposes one field while its behavior lives in declaration merging).

### TeXRA

- **Deep module: `Run`** (`effect/sessions.ts:174-207`). Six members over the run history; since #14395 it is a 118-line view (`effect/runHandle.ts:27-118`, down from 252) with one meaning of leaving: "stopping early stops your reading, not the run" (`sessions.ts:200-201`). `result` returns the stored `RunEnd` with the answer. The peers make the caller dig: pi-durable commits a transaction to read the entry, pi coding-agent's `prompt` returns `void` and the example dumps `state.messages` (`01-minimal.ts:19-22`), and DeepSeek's `finalResponse` is the last assistant text before idle, not attributed to the prompt (`client/src/api.ts:338`).
- **Deep function, pull complexity down: `defineTool`** (`tools/core/definition.ts:68-132`). It validates with every issue, converts ordinary failures into error results, and lets interruption and storage refusals through. The body is `(input) => Effect` (`:60`): cancellation and services ride the fiber. Compare pi coding-agent's five positional parameters (`coding-agent/src/core/extensions/types.ts:656-662`) and DeepSeek's required `output.render` (`core/tools/src/schema.ts:492-497`).
- **Information leakage, define errors out of existence: `session.request`** (`sessions.ts:255-257`). One method takes 12 request kinds (`shared/session/runtimeRequest.ts:44-145`) and answers a 5-case `Outcome` (`:232-249`). Callers narrow it at 11 sites, and one turns an impossible case into a runtime throw (`packages/desktop/src/renderer/projectWorkbench.ts:130`, `if (outcome.kind !== 'done') throw unexpected(outcome)`). Method: `grep -rnE "kind (===|!==) '(done|followUp|forked|preview|runFiles)'"` over the hosts and app, minus one UI payload hit.
- **Pass-through variables, change amplification: launch options spelled three ways.** `StartInput.interactive / helperModel / approval.{policy,delegated}` (`sessions.ts:153-163`) are renamed to `stopAfterCycle / preferHelperModel / approvalPolicy / approveDelegatedWork` (`agent/runtime/rootLaunch.ts:27-55`) at `effect/sessionPrograms.ts:152-161`. The CLI inverts the other way first (`packages/cli/src/runtime/executeCli.ts:188`, `interactive: options.stopAfterCycle !== true`), so a flag is negated twice between host and loop. **Conjoined methods:** `RunsShape.launch` is overloaded for a root launch and a hold (`agent/runtime/runs.ts:68-79`), and each overload has exactly one caller (`sessionPrograms.ts:152`, `controllers/session/deletionCleanup.ts:170`).
- **Overexposure: the embedder door.** The caller must spread `harnessBuiltins` (`index.ts:10-11`); `agentsDir` and `storageDir` are required even for an inline persona in memory (`platform/defaults/sdkPlatform.ts:23-35`); and `platform.roots` is passed twice, because `Sessions.layer` reads process facts (`storageRoot`, `config.catalog`, `globalState`) off a workspace's roots (`effect/processLayer.ts:93-104`) and `open` then takes the same roots (`example/03…:73`). **Information duplication:** `Plugin.tools` is keyed by a registered name (`tools/plugins.ts:107-108`) beside each tool's `definition.name`. `toolTable` never compares the two (`tools/toolTable.ts:224-228`), while run-scoped tools are keyed by `definition.name` (`agentToolResolution.ts:273`).

**Today's merges.** All four removed mechanism without widening an interface. #14395: `Run` became a view, with the same six members, `RunsShape.launch` narrowed from `RunEndResult` to `CommitOrdinal` (`runs.ts:70`), the `OwnedByParent` round trip removed (0 hits in `packages/*/src`) and net −210 code lines. #14396: `RunEndResult.ts` (44 lines) gone, replaced by a 19-line internal `RunReport`, net −64. #14411: the stop decision pulled down into `RunRegistry` (`stopEnd`), `sessionLayer.ts` 716→669 lines, `stopAll` now returns `void`, net −77. #14412: claim taken by the generation, `runLaunchGuard.ts` 317→282, net −63. `RunRegistry` keeps 15 public members over 824 lines. One concept remains exposed: `Run.redirectedFrom` (`sessions.ts:177-180`), so an embedder still learns that a resumed child may hand back its parent.

### pi

- **Deep, somewhat general-purpose: `Submission`** (`durable/src/harness/types.ts:109-114`). With `id`, `status`, `wait` and `abort`, it hides admission, placement and answer, and `wait` returns `done | unanswered`. `Conversation` (13 members, `:780-842`) exposes `commit(tx)` as the one general write.
- **Defaults carry configuration:** "absent: every installed extension" (`durable/README.md:415`); `createRegistry()` includes the built-in tasks, and `Harness.open` refuses a registry without them (`harness/harness.ts:568-572`).
- **Pass-through variable:** every async method takes `context: Context`, 54 times in `harness/types.ts` alone; the caller threads cancellation through every call.
- **Shallow module:** `defineTool` and `defineExtension` are identity functions (`harness/define.ts:6-17`; TeXRA's rule flags the file with 17 elements). The work happens in `harness/tool.ts` (1,127 lines), so responsibility is equal and only its location differs.
- **Overexposure, special-general mixing (coding-agent):** `AgentSession` has 77 public methods and accessors over 4,463 lines (`core/agent-session.ts:379`); replacing discovery means implementing an 11-method `ResourceLoader` (`examples/sdk/12-full-control.ts:36-49`); the tool contract mixes TUI rendering (`renderCall`, `renderResult` with `Theme`, `extensions/types.ts:665-673`) with model fields. pi has three tool contracts (agent `AgentTool`, coding-agent `ToolDefinition`, durable `ToolRegistration`); inferred change amplification while both stacks live.

### DeepSeek (SDK profile `sdk-minimal` unless noted)

- **Deep module: the SDK client.** `DeepSeekHarness` (6 members, `sdk/client/src/api.ts:22`) and `HarnessSession` (3, `:177`) over a runtime process; all 18 options are optional (`client/src/types.ts:24-60`).
- **Unknown unknowns: `Agent` is `{ id }`** (`core/agent/src/types.ts:16-19`). Behavior is reached through declaration-merged context maps (`:21-37`) and factory contracts whose ordering rules fill a 20-line comment (`core/agent/src/index.ts:177-197`). The formal interface is small; the informal one is large and undeclared.
- **Overexposure:** a custom tool is a Cordis plugin (`name`, `inject`, `apply`) loaded by an absolute path in YAML (`docs/user/develop/basic/index.md:48-60`). `defineTool` requires `output.schema` and `render` (`schema.ts:492-497`) where a text default would do. The minimal profile composes 37 plugins (`bundle/sdk-minimal/cordis.patch.yml`, count of `- id:` entries), so which approval, tools or persistence a run has is a property of the deployment, not of the code calling it.

## 3. What TeXRA should do

1. **Give each owner its own tag and remove the `SessionHandle` record** (`agent/runtime/SessionHandle.ts:329-358`, 11 members). Red flag: a pass-through aggregate that every consumer depends on whole. PRD estimate −300 to −350; I did not re-estimate. Peer: pi's `Harness` exposes owners directly (`Conversation`, `Submission`). Keep the prior review's caveat: each member is a real owner, so remove only the duplicate routes. **ALREADY QUEUED (row 9, C1-C5).**
2. **Type `session.request` per kind** with a request-kind to outcome map, so `request({ kind: 'run.fork' })` returns `{ kind: 'forked' }`. Red flags: information leakage, an error not defined out of existence (`projectWorkbench.ts:130`). Change: `shared/session/runtimeRequest.ts`, `effect/sessions.ts:255`, the 11 narrowing sites. Estimate about −10 lines (PRD figure; my site count matches); the gain is the impossible cases removed. Peer: DeepSeek's `HarnessSdkClientRequestMap` indexes results by method (`sdk/protocol/README.md:30-53`). **ALREADY QUEUED** (design-line table, "`session.request` 一扇门 ①"; no row number).
3. **Use one vocabulary for launch options, and split `hold`.** Make the registry accept `StartInput`'s option names, delete the `RootLaunch`/`RootLaunchRequest` wrapper, and give the hold its own member (`runs.ts:68-79`, `rootLaunch.ts:20-62`, `sessionPrograms.ts:152-161`, `deletionCleanup.ts:170`, `executeCli.ts:188`). Red flags: pass-through variables, conjoined methods, a double negation. Estimate −20 to −35 lines: the 43 lines of `rootLaunch.ts:20-62` restate `sessions.ts:146-166`, and the 9-line translation goes. Renaming `stopAfterCycle` in its 16 files is line-neutral. Peer: pi has one `AgentChange` vocabulary from `root()` to `configure()` (`durable/README.md:389-415`). **NEW.**
4. **Make `Plugin.tools` a list keyed by `definition.name`** (`tools/plugins.ts:107-108`, `toolTable.ts:224-228`, the plugin literals in `tools/builtinPlugins.ts` and `packages/texra/src/tools/`). Red flag: one fact stated twice and never checked. About 0 net lines; a class of mismatch errors disappears. Peers: pi `tools: [count]` (`durable/src/harness/types.ts:399`); DeepSeek `ctx.tools.register(defineTool(...))`. **NEW.**
5. **Let the embedder door carry its defaults:** built-ins included unless opted out, and `open()` defaulting to the platform's workspace. Process facts should move off `WorkspaceRoots` onto `AgentPlatform`, so `Sessions.layer` stops reading them from a workspace record (`processLayer.ts:93-104`, `sdkPlatform.ts:66-95`). Red flag: overexposure; it removes 2 of 11 concepts from the minimal program and changes about +5/−5 lines. Peer: pi-durable's extension default (`README.md:415`). Hosts keep passing explicit lists through `processLayer`. **NEW** (row 11's "examples, one concept per file" touches the same examples; the S4 `AgentPlatform` naming item is only a rename).

## 4. What TeXRA should refuse

- **pi's explicit `context` argument.** Effect already carries cancellation and spans in the fiber; adding it would introduce a pass-through variable on every call.
- **One facade class for everything** (pi `AgentSession`, 77 members) and replacement interfaces that must be implemented whole (`ResourceLoader`). TeXRA's wide-records ratchet already forbids this; keep it.
- **Identity `define*` functions.** TeXRA's `defineTool` does real work at definition; do not thin it to a type helper.
- **DeepSeek's YAML-composed deployment as the extension path,** and its `{ id }`-only interfaces with behavior in merged context maps. These make the interface small on paper and move it into informal knowledge. Typed Effect layers and `Plugin` data are the better form.
- **A required renderer per tool** (`output.render`). TeXRA's `string | ToolResult` return is the right default.
- **Per-kind forwarding methods on `Session`** (`session.fork(...)`, `session.compact(...)`). The PRD already rejected them; type the one door instead (item 2).
- **Reading the answer through a storage transaction** (pi `commit(tx => tx.entry(...))`). `Run.result` returning `RunEnd` is better; keep it.
