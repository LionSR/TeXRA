## How the rows were built

### Ids

Every id a report gives is one row.

- **Ids this catalogue adds:**
  - **L1 to L6:** the lead auditor's six findings, numbered here in the order of the root note's
    "Findings by area" table. The L report gives them no ids.
  - **RT1 to RT8:** area R's own R1 to R8, renamed so they do not collide with
    the roots.
  - **V-R1 to V-R24:** V's "Revisit now" rows.
  - **J-b and S-thin:** the J report's and the S report's unnumbered batched sections.
- **Batched sections are one row each:** B9, C11, D8, E11, F7, G11, H11, I12,
  J-b, K11, M11, N11, O9, P8, Q8, RT8, S-thin, T10, U7. Each row's status says
  which sub-items are done.
- V's 54 "Still right" items are not rows. They are cited where they decide a
  status (S9, S10, S15, S16).

Round 1's brief, and the round-2 and round-3 briefs that copied it, did not
list _comment repeats code_, _hard to pick name_ or _implementation
documentation contaminates interface_. That is why the counts below are near
zero for those three. It shows where the area audits did not look; it does
not mean the code is clean there. The lens audits beside this report
(`interface-comments.md`, `names.md`) are the first to search for them.

### Status

- **landed (PR):** on `main`.
  - A round-1 finding carries the PR that landed its root, and the deletion
    list it maps to.
  - Where a root PR's "Left" section, or a spot check on `main`, shows that
    part did not land, the row says so.
  - Spot checks run on `main`: `RootRunClaim`, `callRequests`' parameter list,
    `RunLabels`, `opensStage`, `hasHistoryRows`, `inputClosed`,
    `ProviderErrorClassification`, `backgroundOn`, `helperCall`, `handedDown`,
    `attemptStarts`, `setExitCode`, `installedCommands`, `LatexDiffManager`,
    `allSettledVoid`, `joinOpening`, `ApiKeyStatus` (all still present) and
    `withoutInvalid` (gone).
- **assigned (package):**
  - the round-2 "Who takes what" table;
  - the round-3 package table and its batched-items rule;
  - V's "Owner" column;
  - a merged PR's "follows in A's next PR".

  An open PR is named.

- **refused (id):** an entry in `.agents/docs/refuted-candidates.json`.
  - A finding refused in a PR body or a note, with no entry, is marked
    "refused, no record".
- **open, no owner:** named by no package, lane, step or V row.
  - Also a finding whose step landed without it.
  - Also the three findings the owner set aside with #14773.
- **Mixed rows:** a row whose part has landed is counted by what is left.
  - If the rest has an owner, the row counts as "assigned".
  - If any of the rest has none, it counts as "open, no owner".
  - The status text says which part is which.
