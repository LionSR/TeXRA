## Target structure (after O1)

- `Runs` = `Map<RunId, Fiber>` + the child budget Semaphore. `start(runId, program)`: refuse if present, `forkIn(sessionScope)`, observer deletes. `stop(runId, reason)`: append `run.stop`, then `Fiber.interrupt` (children first: a loop over `facts.children`; detach = `run.detach` batch then no cascade). A run with no fiber: `run.stop` + `run.end CANCELLED` in one batch. `stop` returns `Effect<boolean>`. Deleted: Activation, RunAttempt, attemptOf, attachControls, RunControls, LiveRun (→ Fiber), awaitDrained (→ Fiber.await), withInactiveRunStep + lanes (publisher commit order serializes), stopCause, markStopped, terminate/visited, stoppedAtDisposal, closing/disposed flags (the session scope's closing interrupts the fibers), bornDetached/unbornParent, assertAdmitsChild (a stopped parent's open call cannot launch: it is interrupted), RunLive stays as the one refusal.
- Launch = open then fork: `openRun(runId, registration|activation)` is one transaction in the caller's fiber returning the commit; then `runs.start(runId, loop)`. Deleted: `opened` Deferred, onAdmitted, activationIfOpened, rootRun's raceFirst + uninterruptibleMask, held-trace buffer in enterRun (events after the open publish directly), `settle` callback.
- Resume = `resumeRefusal(facts, config)` (pure: finished/earlierBuild/unusable/blocked/ownedBy) then the same open+start. Second resume of a live run: `{ live: fiber }`. Deleted: openResume, decideResume, resumeQueuedToolUse, restsWith (a caller that wants "the message was taken" reads followUpReceipt, which already exists), answered, wakeRun (= resume with no caller), ResumeHandOff, 'released'.
- End = `endRun(exit)` uninterruptible: `verdict(exit, stopRow)` pure → one `log.transact([cancels, halt, consumed-dropped, closure, run.end])`. A failed transaction fails the fiber once (logged); the run then reads as interrupted at the next open (O4), which is the truth. Deleted: failedEnd, endWith, endActivation, endVerdict/stoppedVerdict split, finalizeRun's lost-notice and backstop levels, beforeEnd's claim line, endIn's raw append, persistFailure/recorded, lastTurn hook (O5: the parent's call writes the child's tool.result).
- Deleted files: ownerLiveness.ts (O1), runLaunchGuard.ts whole (deliverHeld/onHeldResult/clearHeld: O5; closeLeftoverRun/reportInterrupted: O4 + a resumed parent's call finds its child interrupted via resumedAttempt → tool.result says so; runWithLaunchGuard: the launcher's loop ends a failed hand-off with the same endRun), resumability.ts folded into the pure refusal.

## What we give up

- Reference-counted resume: a resume whose caller leaves no longer stops the run. (Owner wants runs to continue.)
- 'released' as a distinct cause: a hand-off's caller leaving is not a stop.
- The end's survival of storage failure: a run whose end could not be written reads as interrupted, not FAILED-with-backstop.
- Two processes driving one store (O1).
