AI models ​

TeXRA connects directly to models from Anthropic, OpenAI, Google, DeepSeek, Moonshot, DashScope, MiniMax, GLM, Meta, and xAI. Pick a model from the dropdown menu in the TeXRA UI or pass --model in the CLI; hover over any option in the picker to see its context window and token pricing.

The model picker: one entry per model, named by its model reference, with a T badge on models that think, and a hover popover showing context window and per-1M token pricing.

Model references. A model is named provider/id, where id is the provider's own API model ID: anthropic/claude-opus-5-5, openai/gpt-6.1-sol. Wherever you type a model (--model or .texra/config.json), you can add:

  • @effort to set the reasoning effort: @low, @medium, @high, @xhigh, or @max (for example anthropic/claude-opus-5-5@high); a few models, such as Muse Spark, also take @minimal
  • @none to turn thinking off, on models that allow it (for example deepseek/deepseek-v4-pro@none)
  • +pro to run an OpenAI model in pro reasoning mode (for example openai/gpt-6.1-sol+pro)

Thinking and non-thinking versions of a model are one entry, not separate models. Without an @effort, TeXRA uses the level you last picked for that model in the model picker, otherwise medium, for every model. Each model remembers its own level, so switching back to a model returns to the level you last used with it. If a model does not offer the level you ask for, TeXRA uses the nearest level it does offer (a tie goes to the higher level, so medium on a model with only low, high, and max runs at high), and the run log says so. The CLI's --model and texra models show also take a model's bare API ID or label when it names exactly one model (claude-opus-5-5, Opus 5.5, or opus55); .texra/config.json takes the reference.

Fable 5.2, Fable 5.1, Opus 5.5, and Sonnet 5.5 (and the older Opus 4.6 through Opus 5, Sonnet 4.6, and Sonnet 5) include the full 1M context window at standard pricing, with no opt-in or beta header required. Haiku 5.5 (anthropic/claude-haiku-5-5) also has a 1M context window, billed at $0.10 / $0.50 per 1M tokens up to 100K input tokens ($0.50 / $2.50 above 100K), with adaptive thinking on by default and @none to turn thinking off. Haiku 4.5, Opus 4.5, and Sonnet 4.5 use a 200K context window.

Claude Fable 5.2 (anthropic/claude-fable-5-2, $8 / $40 per 1M tokens) and Fable 5.1 (anthropic/claude-fable-5-1, $10 / $50) are Anthropic's most capable models. Thinking is always on (adaptive, with summarized reasoning), so they do not take @none. Both support the full reasoning-effort range up to @xhigh and @max, and are eligible for context compaction in tool-use mode.

Claude Sonnet 5.5 (anthropic/claude-sonnet-5-5) costs $2 / $10 per 1M tokens with a 1M context window. Thinking is always on (adaptive), so it does not take @none. It supersedes Sonnet 5 (anthropic/claude-sonnet-5), which is now deprecated.

Claude Opus 5.5 (anthropic/claude-opus-5-5) is built for long-running agentic coding and knowledge work at $4 / $20 per 1M tokens, below Opus 5. Like Fable, thinking is always on, and it accepts the full effort range up to @max.

TeXRA's reasoning-effort selector maps to Anthropic's effort levels automatically: pick anthropic/claude-opus-5-5 or anthropic/claude-fable-5-2 with Extra High (@xhigh) or Max (@max) for the strongest agentic coding and long-horizon tasks. Opus 5.5 and Fable read dense charts, diagrams, and screenshots more precisely than earlier models. TeXRA downscales images above texra.maxImageDimension (default 2000px) before sending, so raise that setting to send higher-resolution figures.

GPT-6.2 Astra (openai/gpt-6.2-astra, $8 / $40 per 1M tokens) and GPT-6 Astra (openai/gpt-6-astra, $10 / $50) are OpenAI's most capable models for the hardest end-to-end work; both support reasoning effort up to @max. GPT-6 Astra is also available in Codex for Pro, Enterprise, and Business Premium subscribers. Note the long-context pricing across the GPT-6 series: prompts above 272K input tokens bill at 2x input/cache and 1.5x output for the full request.

GPT-6.2 Sol (openai/gpt-6.2-sol, $2 / $10), GPT-6.1 Sol (openai/gpt-6.1-sol, $2 / $10), GPT-6.1 Terra (openai/gpt-6.1-terra, $1 / $5), and GPT-6 Luna (openai/gpt-6-luna, $0.10 / $0.50) bring Astra's advances to faster, lower-cost tiers with reasoning effort up to @max and the same 272K long-context threshold. openai/gpt-6.1-sol is the default model in VS Code and the desktop app (the CLI defaults to deepseek/deepseek-v4-pro) and the default for the Codex integration.

Pro mode. Add +pro to a supported GPT model (for example openai/gpt-6.1-sol+pro) to run it in the Responses API's pro reasoning mode, billed at standard token rates rather than a premium tier, for the hardest planning and long-horizon tasks.

Fast mode. Turn on Fast mode under OpenAI in Settings → Models (or in /config in the CLI, or set "texra.model.openaiFastTier": true in the global config.json; a project's .texra/config.json cannot set it) to send OpenAI requests on OpenAI's fast service tier, for models that offer it. Responses come back faster at a higher per-token price (for example $4 / $20 per 1M tokens for GPT-6.1 Sol), and run costs use the fast-tier prices. Read the OpenAI API reference for full capabilities.

Setting API keys ​

Using your own provider API key? TeXRA stores keys in ~/.texra/secrets/, a folder only your user can read, shared by the extension, the desktop app and the CLI; they are never written to settings files.

  1. Open Settings: Select the gear icon in the TeXRA panel header, or run TeXRA: Open Settings from the Command Palette.
  2. Go to the Models page: The API keys list shows every provider with its current key status (Key set, Env, or Not set).
  3. Set the key: Find your provider's row and select the Set API key button, then paste your key. If you don't have a key yet, select the button that opens the provider's API key page (for example Open DeepSeek API key page; its tooltip reads "Get API key from provider").

The Status column shows Key set once the key is stored. To replace a key, set it again; to remove one, select the trash icon. Repeat for each provider you plan to use.

Per-provider settings

Expand a provider's row (select the chevron) to point requests at a custom endpoint, for providers that support it. The endpoint must serve the same API the provider's own does: the OpenAI Responses API for most providers, the Anthropic Messages API for Anthropic and the Gemini Interactions API for Google.

You can also place a .env file in your workspace with variables such as OPENAI_API_KEY. Every task of the project reads it, in the extension, the desktop app and the CLI, so you don't need to enter keys each time.

Already paying for a ChatGPT or Grok subscription? Sign in and skip the API key for those models. Kimi Code and the GLM Coding Plan also run on a subscription you already pay for, authenticated with a plan-specific key instead of a full provider key. Read Quick start → Add a key or connect a subscription.

The ChatGPT section's Advanced → Input token budget (texra.chatgptCodex.contextWindowK) is the input budget for ChatGPT-subscription (Codex) routing, in thousands of tokens, like Codex CLI's model_context_window. Left empty, each model takes the window the Codex backend grants it; a value overrides it for every model, up to 872. Automatic compaction may run earlier, according to the separate compaction threshold, and the context window TeXRA displays adds the model's output budget. OpenAI enforces the real per-account limit: a value above what your plan allows fails and triggers compaction recovery.

Customizing the model list ​

Choose which models appear in the model picker from Settings → Models → Models: toggle them on or off per provider, no JSON required (the choice is saved in TeXRA's user-wide state, not in a settings file, and applies across the extension, desktop app, CLI /model, and assistant delegation). When you sign in to ChatGPT, every model your subscription serves appears automatically without toggling them on one by one.

In the CLI TUI, run /model after a chat starts to see the models your current credentials can run. Mid-session switching is limited to models that share the active model's provider family; other entries are shown disabled with a reason, and switching waits until the current response finishes. To change family, start a new chat with --model.

For headless CLI runs, list what is available with texra models list (or texra models show <model> for details), then pick a default for your project by setting the texra.model key in .texra/config.json, or override per run with --model <model> (an @effort or +pro suffix works here too):

texra models
$texra models list
