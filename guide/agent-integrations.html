Agent integrations ​

TeXRA's assistant can delegate programming tasks—such as running numerical checks or writing figure scripts—to a local coding agent. Two integrations are supported:

  • OpenAI Codex: a sandboxed coding agent on your ChatGPT Plus / Pro plan (or an OpenAI API key). The assistant reaches it through the codex tool. (ChatGPT Pro/Business plans also include monthly API credits for TeXRA's own OpenAI models; see Getting API keys.)
  • Claude Code: Anthropic's coding agent on your Claude Pro / Max plan (or an Anthropic API key). The assistant reaches it through the claude_code tool. (Claude Max/Team plans also include monthly API credits for TeXRA's own Anthropic models; see Getting API keys.)

Each one is set up from its own row on Settings → Plugins. When the assistant uses the tool, the work runs in a side panel on the Tasks view that you can watch live. TeXRA carries on while the side agent works.

Quick start ​

Both integrations follow the same setup flow from the TeXRA Settings.

  1. Open TeXRA: Open Settings (Ctrl+Shift+P) → Plugins ().
  2. Find the OpenAI Codex CLI or Claude Code CLI row and switch it on (both are off by default). When it shows Needs setup, the setup actions expand automatically.
  3. Select Install in terminal, then Sign in to OAuth in your browser.
  4. Reopen Settings (or select Re-check on the Plugins page). The status changes to a green check (tooltip Ready) once TeXRA detects the install.

Each integration has its own row: a Needs setup row expands its setup actions, and Re-check flips it to Ready with a settings summary.

In the terminal client, /plugins lists the same integrations with their state and switches each one on or off. Install and sign in to each CLI with its own installer and sign-in command.

Per-call approval prompts follow Settings → General → Approval: Auto-approve (default) or Ask. Choose Ask to review each launch, or approve all agent work for the task on its first request card. When you approve a single launch, Codex runs in workspace-write mode and Claude Code in acceptEdits; under Auto-approve (or an all-agent-work grant), both run with full permissions. Codex never stops to ask on its own.

Both CLIs are installed once per machine and shared by VS Code, the desktop app, and the CLI. Neither ships inside TeXRA, so TeXRA uses whichever version is installed on your machine.

Windows

TeXRA spawns each CLI binary directly in the same environment as the extension host, so it needs a real .exe, not one of the claude / .cmd / .ps1 shims that a global npm install leaves behind. Claude Code is therefore installed with winget (or its native installer) on Windows, which is what Install in terminal offers there. For Codex, Install in terminal on Windows runs OpenAI's PowerShell installer (irm https://chatgpt.com/codex/install.ps1 | iex), which installs a native codex.exe that TeXRA finds without a restart. TeXRA looks for each CLI in the environment it runs in, so an install inside WSL is found only when TeXRA itself runs inside WSL (the WSL Remote case below), not from a native Windows window.

  • WSL Remote: open TeXRA inside the WSL window before installing.
  • Native Windows: install the CLI on Windows so the real binary is on PATH.

OpenAI Codex ​

Install and authenticate ​

  • Install with npm install -g @openai/codex, or brew install codex (macOS), or the official installer linked from developers.openai.com/codex/cli. Install in terminal picks Homebrew automatically when you have it, so the button works without a Node install; on Windows it runs OpenAI's PowerShell installer instead (see the Windows note above).
  • Sign in with codex login to use ChatGPT Plus / Pro, or set OPENAI_API_KEY in the shell you launch VS Code from to bill against an API account.

Follow-ups ​

To continue an earlier Codex turn instead of starting a fresh one, the calling agent calls codex again with the thread_id it received in the previous delivery. The new prompt joins that Codex session as the next turn. A thread whose turn is still running refuses another until that turn's result has been delivered.

Claude Code ​

Install and authenticate ​

  • Install with npm install -g @anthropic-ai/claude-code, or brew install --cask claude-code (macOS), winget install Anthropic.ClaudeCode (Windows), or the native installer at claude.com/code.
  • Sign in with claude login to use Claude Pro / Max, or set ANTHROPIC_API_KEY (Settings → Models → API keys → Anthropic, or the environment), or run claude setup-token to set CLAUDE_CODE_OAUTH_TOKEN. With none of these set, the CLI falls back to any existing claude login session.

Running an integration ​

Turn the integration on under Settings → Plugins, then ask the assistant:

Use codex to sketch a minimal FastAPI server that returns a JSON healthcheck.

Use claude_code to add a --dry-run flag to the build script and update its tests.

When the tool fires:

  1. A new stream tab opens on the Tasks view labelled codex or claude_code.
  2. You see the side agent's reasoning, the commands it runs, the file changes it makes, and any web searches (), all live.
  3. When the turn ends, the run shows Completed. Each call is one turn: to send a follow-up, the agent calls the tool again with the thread_id or session_id the result carried. Select Stop to end a turn early.
  4. The result (final message and token cost) is handed back to the assistant (or helper agent) that asked for it, which then continues its own work.

Both tools deliver their result as a follow-up message, so they are not available in a one-shot run such as texra run; there the assistant delegates to a helper agent instead.

GitHub activity ​

The assistant follows a pull request's reviews and CI, an issue or a repository with the gh command line in its shell, and comes back to check again by scheduling itself a later turn. The bundled github skill has the commands; the assistant reads it only while Enable skills for agents is on (Settings → Agents → Skills, or texra.skills.enabled; off by default).

  • Sign in with gh auth login in a terminal, or start TeXRA with GH_TOKEN set. TeXRA stores no GitHub token of its own.
  • Nothing polls in the background: each look is a turn the assistant scheduled, at least a minute after the last. A scheduled turn is kept by the running TeXRA process; if TeXRA is closed when one is due, it runs once, late, the next time the project is opened. Stopping the task cancels what it scheduled.
  • A one-shot run such as texra run cannot be continued later, so it can check once (or wait on gh pr checks --watch) but not follow over time.

MCP servers ​

TeXRA supports local stdio Model Context Protocol servers:

  • Plugin-bundled MCP servers (recommended): any MCP servers included in an installed plugin are automatically available to the assistant while that plugin is enabled.
  • Manual ~/.texra/mcp.json: open via Settings → Plugins → Open mcp.json (same format as Claude Code's .mcp.json). Note: servers listed only in ~/.texra/mcp.json are currently available only to custom runs/scripts that explicitly request mcp__<server>__<tool> (or mcp__<server>__*) — the default assistant does not automatically load them yet.
json
{
  "mcpServers": {
    "notion": {
      "command": "npx",
      "args": ["-y", "@notionhq/notion-mcp-server"],
      "env": { "NOTION_TOKEN": "ntn_..." }
    }
  }
}

Server names may use letters, digits, _, and - (up to 32 characters, no __, not ending in _). Servers must support MCP revision 2025-11-25 (TypeScript SDK 1.25+); incompatible or failing servers are skipped with an explanation in the transcript.

  • Approval: Every MCP tool call uses the same approval rules as shell commands (Settings → General → Approval). Headless runs require Auto-approve to call MCP tools.
  • Lifecycle: A server starts on first use, is shared by tasks in the project, and stops 30 minutes after the last task finishes.
  • Environment: Inherited environment variables containing KEY, TOKEN, SECRET, PASSWORD, or CREDENTIAL are stripped so provider keys are never leaked; pass required credentials explicitly in env.
  • Limits: Calls time out after 60 seconds, and output over 200,000 characters is truncated in the middle.

Not yet supported: a project-level .texra/mcp.json, HTTP servers, servers that change their tool list while running, and MCP resources and prompts.
