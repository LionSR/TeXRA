TeXRA ​

An open-source AI theorist for VS Code, desktop, and the terminal. It handles real theory work: deriving results, checking derivations in Wolfram, and formalizing proofs in Lean 4, splitting large jobs across helper agents and programs. Manuscript preparation, LaTeX tooling, and figures sit alongside your research project.

Why multi-agent ​

Theoretical work depends on long chains of steps: a sign error in Section 3 breaks Appendix C, a Lean proof needs the right lemma to close a goal, and a numerical script has to match an analytical formula. The manuscript has its own constraints: uniform notation across sections, real citations in BibTeX, and figures that compile cleanly.

General-purpose chatbots struggle with this:

  • Hallucinated citations: without grounded search, models invent references.
  • Lost structure: a single prompt rarely keeps theorem environments, \label/\ref links, BibTeX, and multi-file projects straight at once.
  • No verification: raw text output gives you no way to check an algebra step, type-check a proof, or diff what changed.
  • No tools: no WolframScript, no Mathlib search by type signature, no compiler in the loop.

TeXRA's assistant and programs call real tools and return verifiable output.

Three apps, one system ​

The VS Code extension, the desktop app, and the texra CLI share the same assistant, programs, credentials, and task history. A task started in the CLI appears live in the extension and desktop Tasks list, and vice versa.

TeXRA works in two ways:

Document programs

Run a structured pipeline → save versioned output files with a diff.

editannotateenhanceapplytranscribeslidesposter
.tex in → improved .tex + latexdiff
The assistant

Works conversationally → read & edit files, search, compile, iterate.

reviewsearchderivesolveexperimentcodesimplifytestfix LaTeXlatexdiff
arXivLeanWolframcompilefilesshell

A program runs rounds of a helper agent and checks each in code; the assistant works conversationally with grounded tools.

TeXRA combines three mechanisms: reflection (critiquing and revising output), tool use (checking work against compilers, language servers, and search APIs), and planning (breaking a problem into steps and adapting as results come back).

Mathematicians

Complex theorem environments, notation consistency across long proofs, Lean 4 formalization.

Theoretical physicists

Multi-file manuscripts with heavy equation environments, Feynman diagrams, large bibliographies.

Numerical methods, algorithm descriptions, convergence plots, reproducible workflows.

Thesis chapters with consistent notation, literature surveys in new subfields, talks from written work.

Research groups

Collaborations where every change is traceable and auditable by co-authors and referees.

Privacy and data handling ​

Bring-your-own-key mode. API calls go directly from your machine to the model provider you chose. TeXRA does not sit between you and the provider. Your unpublished proofs, manuscripts, and API keys never leave your machine except to the provider endpoint.

Provider subscriptions (ChatGPT, Grok, Kimi Code and the GLM Coding Plan). Requests still go straight from your machine to that provider: ChatGPT and Grok via OAuth sign-in, Kimi Code and the GLM Coding Plan via a plan-specific key. ChatGPT and Grok connect from the Settings → Models → Subscriptions tab (or texra auth chatgpt login / /login in the CLI); Kimi Code and the GLM Coding Plan take their key under Models → API keys.

API keys, whichever mode you use, stay on your machine, in one owner-only secrets/ folder under ~/.texra that the extension, the desktop app and the CLI share (readable by your user alone; not keychain-encrypted). You can also supply them via environment variables or a .env file in your project.
