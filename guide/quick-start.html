Quick start guide ​

On a fresh install, the setup assistant walks you through connecting a model, checking your environment, and running a first task. This page is the reference for the New task view in VS Code and its CLI equivalents.

draft.tex — texra-sample
New task Tasks
Polish draft.tex: tighten the abstract and fix the awkward phrasing in §2. Keep my notation.
assistant
Sonnet 5.5
% sample project
\begin{abstract}
We present a novel and efficient method for the
estimation of spectral gaps in random regular
graphs, that is both fast and accurate.
\end{abstract}
\section{Preliminaries}
Let $G$ be a $d$-regular graph on $n$ vertices.

The New task view: pick an agent and a model, write one sentence that names your file, and select Start task.

Overview ​

Editing a document typically takes five steps:

  1. Pick an agent and model
  2. Write a short instruction that names your file
  3. Select Start task
  4. Approve the program run the agent proposes
  5. Review the diff

💡 Tip: Inside VS Code you can open the Get started with TeXRA walkthrough from the Get Started page (or by running TeXRA: Open Getting Started Walkthrough). It tells the same story in four steps (connect a model, open your paper, run the setup assistant, your first task) and links directly to the relevant commands.

Prefer the terminal?

This guide walks through the VS Code extension. If you installed the CLI, the same agents run from the command line: start an interactive session with texra chat, or run a single program with texra run edit --input draft.tex. Run texra agents list to see the agents available.

Add a key or connect a subscription ​

A credential is the one step no agent can do for you. On a fresh install, the Connect a model card in the TeXRA panel offers the two main access choices; other subscriptions connect from Settings:

  1. Use your own API keys: Anthropic, OpenAI, Google, and more. Open the Models page (the gear icon at the top of the TeXRA panel) and set your provider's key in the API keys list, or place a .env file in your workspace with variables like OPENAI_API_KEY.
  2. Use ChatGPT subscription: OpenAI models through your ChatGPT plan. Open the Settings Models page and use the Subscriptions sign-in section.
  3. Another provider subscription (from Settings, not the card): Grok (xAI), Kimi Code, and the GLM Coding Plan also run on a plan you already pay for. Connect them from the same Models page.

The full per-provider key reference (the API keys list, its Set / Get / Remove actions, and per-provider settings) lives in Models → Setting API keys.

No TeXRA account

There is no TeXRA sign-in. Every agent and program ships bundled and runs on the credential you configured above.

Once a credential is in place, the setup assistant takes it from here: one conversation that checks your environment and runs your first polish, ending at a diff. First run is the manual mirror of that conversation.

CLI credentials

The terminal uses the same paths: provider env vars for your own keys, texra auth chatgpt login for a ChatGPT subscription, texra auth grok login for a Grok (xAI) subscription, or /login in a chat to manage the ChatGPT and Grok sign-ins. Running texra without any of these opens the chat with a Connect a model panel instead of an error. texra setup is the terminal counterpart of the setup assistant: it walks you through a ChatGPT sign-in or an API key, then your environment, agents, and first task. Read the Authentication section of the CLI guide.

The New task view in detail ​

Open the TeXRA panel from the TeXRA icon in the Secondary Side Bar, or run TeXRA: New Task (Ctrl+Alt+M, Cmd+Option+M on macOS).

Choose agent, model, and instruction ​

The dropdown menus at the bottom of the instruction box pick the agent and the model (e.g. Sonnet 5.5, whose id is anthropic/claude-sonnet-5-5). The agent menu lists each agent once, the default first. Every agent chats; the default, assistant, can be asked for a document edit, and orchestrator splits a larger job across other agents.

Then say what you want, and on which file, in the text area:

Polish main.tex: improve the clarity and flow, and make the technical
explanations more accessible. Fix grammatical issues and awkward phrasing.
Keep the terminology consistent and do not change the equations.

Effective Instructions

Be specific about your objectives: state both what the agent should improve and what constraints (notation, theorem numbering, environment structures) it must preserve.

To send figures or other media along, use Attach in the instruction box.

Approve the program run ​

The New task view does not list programs and has no file section of its own. For a document edit, the agent proposes a run of one of the programs (edit for a polish), and the proposal card shows the program, the instruction and the files. Approve it, or select Edit to change it first: the launch form opens on the proposal with a Documents and attachments section.

  1. In the Input group, use Add input files to pick the documents the program revises. If you have several .tex files open and want them all, use Add opened files as input.
  2. (Optional) Use the same buttons in Context to add read-only references or preamble, and Media to add figure files.

Multiple Files

Save Prompts for Later

For advanced debugging, enable the texra.debug.saveModelIO setting in .texra/config.json to store the generated prompt alongside other debug artifacts.

Review results ​

  1. When the program's run completes, VS Code opens the final revision from the run folder (for edit, r1/draft.tex, keeping your input filename).
  2. Inspect the proposed edits; the scientific judgment stays yours. Compare the original and modified versions with either tool:

    • Tasks view diff: Under Generated files, select a file's Compare with base button to compare the original file against the generated run-storage output.

      draft.tex ↔ r0/draft.tex (Working Tree) — texra-sample

      VS Code's diff editor opens with the first revision (r0/draft.tex) on the left and your original on the right: improved text in green, removed text in red.

      You can accept reviewed outputs from the Tasks view after comparing the changes.

    • TeXRA's LaTeXdiff feature: Use a file's latexdiff button, or LaTeXDiffs… in the panel's ⋯ menu, for a compiled, visual comparison. It creates a PDF with additions highlighted in blue and deletions in red.

From the CLI ​

The same agents and programs run from the terminal. After npm install -g @texra-ai/cli (Node.js 22.22.2 or later in 22.x, or Node.js 24.15 or later) or brew install texra-ai/tap/texra:

bash
# Set ANTHROPIC_API_KEY / OPENAI_API_KEY in your shell, or connect a subscription:
texra auth chatgpt login

# Or let the guided setup handle credentials, environment, and your first task:
texra setup

# One-shot run (prints the revised file's path; --output copies it to a file you name):
texra run edit --input draft.tex \
  --instruction "Improve clarity; preserve math and citations."

# Or open an interactive chat:
texra chat

TIP

A Claude Max or Team plan includes monthly API credits that an Anthropic API key can spend once you link a Console organization to the plan. A ChatGPT Pro or Business plan includes monthly API credits that an OpenAI API key can spend once you claim them for an API organization you own.

texra run
$texra run edit --input draft.tex --instruction "Improve clarity; preserve math and citations."
  • Revision 1: draft
  • Revision 2: review and correct
…/executions/9f3a6c81d24e/r1/draft.tex

What a one-shot run looks like: revisions stream as progress, then the full path to the revised document prints on stdout.

Run history is shared with VS Code, so a run started in the CLI shows up in the extension's Tasks view (and vice versa). Read the TeXRA CLI guide for sign-in, workspace defaults, and headless output formats.

Common quick tasks ​

Some common tasks to try with TeXRA. Ask the agent in the New task view, or run the program from the terminal:

TaskAsk the agentFrom the terminal
Proofread a draft"Proofread draft.tex: fix typos, grammar and LaTeX formatting only."texra run edit --input draft.tex
Polish writing style"Polish draft.tex for clarity and flow; keep the math and citations."texra run edit --input draft.tex --instruction "Polish for clarity and flow"
Review as a first reader"Annotate draft.tex as a first-time reader would."texra run annotate --input draft.tex --instruction "Read as a first-time reader"
Build slides from the paper"Turn paper.tex into a slide deck."texra run slides --input paper.tex --output slides.tex

Understanding the output ​

A completed run writes everything into the run folder under run storage, one folder per revision (r0/, r1/, …). Each revision folder holds the revised document, which keeps your input filename (draft.tex, not output.tex), and the model's raw reply (output.xml); the run's latexdiff PDFs go under diff/r{revision}/ and compile logs under compile/:

run storager{revision}/<input-filename>
r0/Revision 1
  • draft.texOutputinput filename preserved
  • output.xmlReplythe model reply
r1/next revision, same layout
diff/r0/latexdiff PDFs
compile/compile logs

One folder per revision: the revised document at r{revision}/<input-filename> with the model's reply; latexdiff PDFs under diff/ and compile logs under compile/ sit beside the revision folders. Each further revision repeats the layout in r1/, r2/, …

The CLI writes the same per-revision tree under executions/<run-id>/ in the project's storage folder under ~/.texra, which VS Code shares. Read First run for the terminal walkthrough.
