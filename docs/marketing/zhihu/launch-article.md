# 我给论文写作做了一个 AI 理论助手：TeXRA 今天正式发布

利益相关：本人是 TeXRA 的开发者。这是一篇产品介绍文章，请带着这个前提阅读下面的每一句话。

先说结论：TeXRA 是一个面向论文的 AI theorist（AI 理论助手）。它在你真实的 LaTeX 文档上做真实的科研工作：润色、查推导、审稿、形式化，并且把每一处修改都以 diff 的形式交给你审批。你不点头，文件一个字符都不会动。它有三种形态：VS Code 插件、终端 CLI、桌面应用，三端共享同一份运行历史。登录即有免费模型额度，国产模型（DeepSeek、GLM、Kimi、MiniMax、Qwen）全部支持。如果你写代码用过 Copilot 或 Cursor，可以这样理解：论文写作终于也拿到了同等待遇的工具。

下面给论据。

## 一、为什么不是「又一个套壳聊天机器人」

写代码的人这几年陆续拿到了 Copilot、Cursor、Claude Code，AI 直接进了编辑器和终端。做研究的人拿到了什么？浏览器里的一个聊天框，外加无穷无尽的复制粘贴：把 LaTeX 源码贴进去，把回答贴回来，手工对照哪里改了，祈祷它没有顺手吃掉一个负号。

TeXRA 要补的就是这个缺口：让 AI 在研究者真正工作的地方干活，也就是你的 .tex 文件、你的编辑器、你的终端。

架构上，它和聊天机器人有三点本质区别。

**第一，两类 agent 架构。** 一类是 reflection 工作流 agent（如 polish、correct、ocr），面向文档任务：读入整份文件，带着模型自带的推理循环产出完整修改稿。另一类是 tool-use agent（如 review、research、latexFixer），面向对话式研究任务，可以调用文件、shell、搜索、Wolfram 等 56+ 内置工具，但每一次工具调用都要过逐条审批门：agent 想读哪个文件、跑哪条命令，你都看得见、拦得住。内置 agent 一共 44 个，其中还有 5 个专门做 Lean 4 形式化的。

**第二，diff 审批模型。** 所有对文档的修改都不直接写入你的文件，而是先渲染成 latexdiff PDF：红色删除线是删掉的，蓝色是新增的，数学模式安全，只聚焦改动页。你像审别人的修改稿一样过一遍，接受或拒绝。

**第三，版本化的 run storage。** 每次运行的产物先存进版本化的运行存储，历史可查、可回滚、可恢复运行，三个端共享同一份记录。聊天机器人聊完即忘；这里每一次 run 都是有据可查的档案。

## 二、三个真实场景

**场景一：带凭据的润色。** （以下均为示例文档。）选中一篇旧稿的引言节，跑 polish agent。它重写表达、理顺逻辑，但产物不落盘，停在 run storage 里。点开生成的 latexdiff PDF：红色删除线标出删掉的句子，蓝色标出新写的，公式环境原样保留。满意就接受，文件这时才真正更新；不满意就拒绝，原文毫发无损。全程你没有复制过一行 LaTeX。

**场景二：查推导。** 怀疑第三节一处推导有问题（示例推导），在 review agent 的对话里圈出来让它核对。它逐行重推，指出从式 (12) 到式 (13) 时一个交叉项的符号翻了；接着调用 Wolfram 工具代入数值验证，确认原式与修正式在测试点上确实对不上；最后把修正作为 diff 提出来。注意这个顺序：先独立重推，再机器验证，最后才动文档，而且动不动仍然由你决定。

**场景三：终端里的多 agent 协作。** 打开终端，`texra chat` 进入交互式 TUI，或者直接 `texra multi-agent run` 跑一个团队预设，比如 Physicist（内置 5 个预设：物理学家、数学家、计算机科学家、Lean 项目、软件工程师）。orchestrator 用旗舰推理模型拆解任务、派活，子任务交给更便宜的 DeepSeek V4 Flash。进度实时滚动，想盯某个子 agent 就切到 focused subagent view 看它的完整过程；它要读文件、跑 shell 命令，逐条弹出来等你批准。

**一个意料之外的用法：投稿前先被它骂一遍。** criticize agent 会在稿子里插入 `\criticize{意见}{严重度}{置信度}` 形式的行内批注，相当于提前请一位不留情面的内部审稿人过稿。被自己的工具批注到怀疑人生，总好过在审稿意见里看到同样的话。

## 四、学术伦理：辅助与代写的边界

学术圈对 AI 写作的警惕完全正当，所以这一节不绕弯子。

TeXRA 的定位是辅助，不是代写。这不是一句口号，而是落在三个设计上的：

1. **作者始终在控制回路里。** 没有任何修改能绕过你落进文件，每一处改动都是一个你看过、批准过的 diff。论文里的每一个判断最终是你的判断，责任也是你的。
2. **工具偏向严谨而非产文。** criticize 负责往稿子里插批评性批注，review 负责验证推导是否成立，verifyFix 跑三阶段的验证与修复循环。这套东西更像一个不知疲倦的内部审稿人，而不是枪手。
3. **痕迹可审计。** 版本化 run storage 留存了每次运行、每个 diff、每次批准。你随时能回答「这一段哪些是 AI 建议的、我接受了什么」。

两句实在话。第一，请遵守目标期刊、会议和所在机构关于 AI 使用与披露的规定，工具不替你做这个决定。第二，模型会出错，签字的是你。TeXRA 的整个架构建立在「模型需要被验证」这个前提上，而最后一道验证，永远是作者本人。

## 五、模型与供应商：国产模型是一等公民

国内同行最关心的两件事：能不能用国产模型，贵不贵。

TeXRA 目前接入 7+ 家供应商：Anthropic（Claude Opus 4.8，1M 上下文；Claude Fable 5，常开自适应思考）、OpenAI（GPT-5.5 与 GPT-5.5 Pro）、Google Gemini，以及 DeepSeek（V4 Flash 和 Pro）、GLM（智谱）、Kimi、MiniMax、Qwen（通义，DashScope 接入）、xAI Grok，可走 OpenRouter 或兼容端点。6+ 个模型家族支持扩展思考，推理过程流式可见，思考力度从低到最大可调。

多 agent 团队支持混合模型：旗舰推理模型当 orchestrator 负责统筹，DeepSeek V4 Flash 这类又快又便宜的模型跑子任务。同一个团队里每个成员可以用不同的模型，账单上的差别非常可观。

## 六、怎么获取，花多少钱

- 官网与文档：texra.ai
- VS Code 插件：Marketplace 搜 TeXRA（Cursor、Windsurf 同样可装，Open VSX 也有）
- 终端 CLI：`npm i -g @texra-ai/cli`（Node 22.9 以上），或 `brew install texra-ai/tap/texra`
- 桌面应用：texra.ai 下载

费用分三层。GitHub 或 Google 登录后自带免费模型额度，每月额度在 Settings 里直接可见；学术研究者可以申请 Researcher Access Program，提供免费托管额度，足够在真实工作上跑完整的 orchestrator 加专家阵容；高级用户自带各家 API key（加密存储），免费额度用尽自动回退到个人 key。

TeXRA 刚刚公开发布，我拿不出「多少研究者在用」这样的数字来背书。能给的只有上面这些可以亲手验证的事实：装上，找一篇旧稿，跑一次 polish，看看那份红蓝相间的 PDF。如果复制粘贴对你来说够用，继续用聊天框完全没问题；如果你和我一样，受够了在浏览器和编辑器之间搬运 LaTeX，欢迎来试，也欢迎在评论区把它骂醒。骂得有道理的，都会变成 issue。
