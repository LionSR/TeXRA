我们做了一个专门给学术研究者用的 AI LaTeX 助手。不是套壳 ChatGPT，是真正理解学术写作痛点的工具。

## 一个真实的故事

去年十二月，我在赶一篇 NeurIPS 的 submission。

凌晨两点，Reviewer 2 的 major revision 要求还躺在邮箱里。三十多条 comments，涉及理论推导、实验补充、文献对比。DDL 还剩五天。

我打开 ChatGPT，把论文贴进去，问它："帮我改一下这段证明的表述。"

它给了我一个看起来很漂亮的回答。

问题是——公式是错的。符号前后不一致。更要命的是，它把我论文里已经定义好的 notation 给换掉了。

我花了两个小时才发现这个 bug。

**这就是我开始做 TeXRA 的原因。**

## 学术写作的 AI 工具，为什么都这么难用？

我跟很多 PhD 朋友聊过这个问题。大家的槽点惊人地一致：

### 槽点一：通用 AI 不懂 LaTeX

ChatGPT 是个很好的聊天工具。但它不是 LaTeX 专家。

它不知道 `\label{}` 和 `\ref{}` 的对应关系。它搞不清楚 `equation` 和 `align` 环境的区别。它会把你精心排版的公式改得面目全非。

更别说 BibTeX 了。它生成的引用格式经常是错的，DOI 是编的，作者名字的顺序也有问题。

### 槽点二：改完不知道改了啥

用 AI 改论文最恐怖的事情是什么？

是你不知道它到底改了什么。

你给它一段 5000 字的 section，它返回一段"优化后的版本"。看起来差不多，但哪里不一样？它删了什么？加了什么？改了什么？

你只能一行一行对比。或者直接信任它——然后在 submission 之后发现它把你的核心贡献偷偷改掉了。

### 槽点三：公式推导靠幻觉

这是最致命的问题。

AI 模型本质上是语言模型，不是数学引擎。它们可以生成"看起来像"数学证明的文本，但不保证逻辑正确。

我见过 GPT-4 把 $O(n \log n)$ 的算法"证明"成 $O(n)$ 的。我也见过 Claude 在积分里面漏掉一个负号。

学术论文里，一个错误的公式就是一篇 reject。

### 槽点四：文献引用靠猜

"帮我找几篇相关论文。"

然后 AI 给你编了五个不存在的论文标题，配上虚构的作者和年份。

这不是 AI 的错——它的训练数据里确实有这些模式。但对于学术写作来说，这是不可接受的。

## TeXRA 的设计哲学

基于这些痛点，我们设计 TeXRA 时遵循了几个核心原则：

### 原则一：专业化，而非通用化

TeXRA 不是"又一个 AI 助手"。它是**专门为学术 LaTeX 写作设计的工具**。

我们有不同的 Agent 处理不同的任务：

| Agent | 功能 | 设计理念 |
|-------|------|----------|
| `correct` | 校对纠错 | 只修正错误，绝不改变内容和风格 |
| `polish` | 润色提升 | 两轮推理：规划 → 执行 → 反思 |
| `draw` | TikZ 绘图 | 教授级别的专业图表生成 |
| `research` | 研究计算 | Wolfram 引擎，符号推导有保证 |
| `search` | 文献检索 | arXiv + Crossref，真实来源 |

每个 Agent 都有针对性的 prompt engineering，而不是一个通用 prompt 打天下。

### 原则二：可验证，可审计

这是 TeXRA 最核心的设计：**你永远知道 AI 改了什么**。

我们内置了 `latexdiff` 集成。每次修改后，你都能看到精确的差异对比：
- 删除的内容用红色标注
- 新增的内容用蓝色标注
- 数学公式的修改可以细化到单个符号

更重要的是，**每次修改都需要你明确批准**。AI 不会偷偷改你的论文。

### 原则三：数学靠引擎，不靠幻觉

TeXRA 的 `research` agent 集成了 Wolfram Language 计算引擎。

这意味着什么？

```
用户：验证一下这个积分 ∫₀^∞ e^(-x²) dx = √π/2

TeXRA：让我用 Wolfram 引擎验证...

Integrate[Exp[-x^2], {x, 0, Infinity}]
→ Sqrt[Pi]/2 ✓

结果正确。我还可以展示推导过程：
使用高斯积分公式，配合变量替换...
```

不是 AI "觉得"这个积分等于什么，是**计算引擎精确求解**的结果。

对于复杂推导，我们还会：
- 用具体数值进行验证
- 检查收敛性条件
- 验证微分方程的解是否满足原方程

### 原则四：引用靠数据库，不靠猜测

TeXRA 直接对接 arXiv API 和 Crossref API。

当你说"帮我找相关论文"时，我们是**真的去搜索学术数据库**，不是从训练数据里编造。

每一条引用都有：
- 真实的 DOI
- 可验证的作者信息
- 正确的 BibTeX 格式
- 可以直接点击访问的链接

## 核心功能深度解析

### 功能一：智能校对（Correct Agent）

**场景**：DDL 前最后检查，需要快速修复所有 typo 和 LaTeX 语法问题。

**能力**：
- 拼写和语法修正
- LaTeX 语法验证
- `\label` / `\ref` 一致性检查
- 数学符号规范化（如确保 $\mathbb{R}$ 而非 $R$ 表示实数集）
- chktex 风格规范检查

**关键特性**：Correct Agent 的设计原则是"最小干预"。它只修复明确的错误，绝不会"优化"你的表达方式。你的声音，你的风格，完全保留。

### 功能二：深度润色（Polish Agent）

**场景**：Reviewer 说"writing needs improvement"，需要提升语言质量但保持技术准确性。

**工作流程**：
```
第一轮：规划阶段
├── 分析当前文本的优缺点
├── 识别需要改进的具体位置
└── 制定详细的修改计划

第二轮：执行阶段
├── 按计划逐项修改
├── 确保每个改动都有明确目的
└── 保持术语和符号一致性

第三轮：反思阶段
├── 批判性审视修改结果
├── 检查是否引入新问题
└── 提出进一步改进建议
```

这种"三轮推理"设计确保了修改质量。AI 不是一次性给你答案，而是经过深思熟虑的迭代优化。

### 功能三：专业绘图（Draw Agent）

**场景**：需要论文级别的 TikZ 图表，但不想花三小时调 coordinates。

**能力**：
- 从文字描述生成 TikZ 代码
- 优化现有图表的视觉效果
- 确保与正文的交叉引用正确
- 生成信息密度高、视觉清晰的学术图表

**示例**：

```latex
用户：画一个神经网络结构图，三层，输入层 4 个节点，
      隐藏层 6 个节点，输出层 2 个节点

TeXRA：[生成专业的 TikZ 代码]
      - 节点对齐
      - 连接线清晰
      - 标签规范
      - 可直接编译
```

### 功能四：研究计算（Research Agent）

**场景**：推导过程卡住了，需要验证某个数学结论。

**能力（基于 Wolfram Language）**：
- 符号积分/微分
- 级数展开
- 矩阵运算
- 方程求解
- 最优化问题
- 微分方程
- 概率分布

**核心优势**：这不是 AI 在"推理"数学，这是专业的计算代数系统在运行。结果是精确的，不是"可能正确的"。

### 功能五：文献检索（Search Agent）

**场景**：需要补充 related work，找最新的相关研究。

**数据源**：
- **arXiv**：预印本搜索，支持按作者/标题/摘要检索
- **Crossref**：正式发表论文，DOI 验证
- **Web**：补充性搜索，但会标注来源类型

**工作方式**：
```
用户：找一些 2024 年关于 diffusion model 在 text-to-image
      领域的重要论文

TeXRA：
├── 搜索 arXiv（cs.CV + cs.LG，2024 年）
├── 交叉验证 Crossref（已发表的）
├── 区分 peer-reviewed vs preprint
└── 返回结构化结果：
    - 标题、作者、年份
    - 真实 DOI / arXiv ID
    - 简要摘要
    - BibTeX 条目
```

### 功能六：格式转换

**Paper → Slides（paper2slide）**：
- 自动提取核心贡献
- 生成 15-20 页 Beamer slides
- 保留关键公式和图表
- 适合学术演讲的 bullet points

**Paper → Poster（paper2poster）**：
- 学术海报专用布局
- 数学内容完整保留
- 视觉层次分明
- 适合 A0/A1 打印

**Audio → LaTeX（transcribe_audio）**：
- 会议/讲座录音转文字
- 自动识别说话人
- 口述公式转 LaTeX 格式
- 分段整理

## 模型生态

TeXRA 不绑定任何单一 AI 提供商。你可以根据任务选择最合适的模型：

### 支持的模型（部分列表）

**Anthropic**
- Claude Opus 4.5（最强推理）
- Claude Sonnet 4.5（性价比之选）
- Claude Haiku 4.5（快速响应）

**OpenAI**
- GPT-5.2 / GPT-5.1
- o3 / o4（推理模型）
- o1-pro（深度思考）

**Google**
- Gemini 2.0 Flash / Pro / Ultra

**国产模型**
- DeepSeek V3 / R1（推理模型）
- Moonshot（超长上下文，100万 tokens）
- Qwen Max / Plus / Turbo
- 通义千问系列

### 为什么这很重要？

不同任务适合不同模型：
- **复杂推导**：用 o3 或 Claude Opus，它们的逻辑推理更强
- **快速校对**：用 Haiku 或 DeepSeek，响应快、成本低
- **长文档**：用 Moonshot，100 万 token 上下文
- **成本敏感**：用 DeepSeek 或 Qwen，性价比极高

TeXRA 让你自由选择，并且实时追踪 token 消耗和成本。

## 典型工作流示例

### 场景：Major Revision 五日攻坚

**Day 1：理解 Comments**
```
1. 用 `search` agent 研究 reviewer 提到的相关工作
2. 用 `research` agent 验证 reviewer 质疑的数学推导
3. 制定修改计划
```

**Day 2-3：内容修改**
```
1. 用 `chat` agent 交互式修改各个 section
2. 用 `draw` agent 重绘被批评的图表
3. 用 `research` agent 补充理论证明
```

**Day 4：全文润色**
```
1. 用 `polish` agent 提升语言质量
2. 用 `correct` agent 最终校对
3. 检查所有 latexdiff 差异
```

**Day 5：生成材料**
```
1. 用 latexdiff 生成 diff PDF（给 reviewer）
2. 写 response letter
3. 最终检查，提交
```

## 安装与配置

### 快速开始

```bash
# 1. 在 VS Code 中安装 TeXRA 插件
# 搜索 "TeXRA" 并安装

# 2. 配置 API Key
# 打开命令面板 (Cmd/Ctrl + Shift + P)
# 搜索 "TeXRA: Set API Key"
# 选择你的模型提供商并输入 key

# 3. 开始使用
# 打开任意 .tex 文件
# 右键 → TeXRA 菜单
# 或使用快捷键
```

### 系统要求

- VS Code 1.99.3+
- TeX Live / MiKTeX / MacTeX（用于 LaTeX 编译）
- Perl（用于 latexdiff 和 latexindent）
- （可选）ImageMagick/GraphicsMagick（用于图像处理）

### API 配置

TeXRA 使用你自己的 API key，这意味着：
- **隐私**：你的论文不经过我们的服务器
- **成本透明**：直接按提供商定价付费
- **无订阅**：用多少付多少

## 写在最后

TeXRA 不是要取代你的学术写作能力。

它是一个工具，帮你处理那些繁琐但重要的事情：
- 检查 typo
- 验证公式
- 查找文献
- 生成图表
- 格式转换

把时间留给真正的研究工作——**思考问题，设计实验，提出创新**。

这些，是 AI 做不了的。

## Q&A

**Q: 我的论文数据会被发送到哪里？**

A: 只发送到你配置的 API 提供商（如 OpenAI、Anthropic）。TeXRA 本身不收集任何数据。

**Q: 支持中文论文吗？**

A: 支持。所有 Agent 都能处理中文 LaTeX 文档。我们也在开发专门的中文润色 Agent。

**Q: 免费吗？**

A: TeXRA 插件本身免费开源。你需要自备各模型提供商的 API key，费用取决于你的使用量。

**Q: 和 ChatGPT Plus 相比成本如何？**

A: 取决于使用量。如果你只是偶尔用，按 API 计费会便宜很多。如果你大量使用，可能差不多。但 TeXRA 提供更多功能和更好的学术支持。

**Q: 遇到问题怎么办？**

A: GitHub Issues 或者邮件联系我们。我们是做学术的人，做给做学术的人用的工具，我们懂你的痛点。
