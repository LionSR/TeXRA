## How this was produced

A multi-agent workflow: five parallel read-only maps — (1) error normalization, (2) error lifecycle/boundaries, (3) observability channels, (4) layering/DI status against the two prior plans, (5) prior-art study of four mature agent stacks (Anthropic TS SDK, Claude Agent SDK, Vercel AI SDK v6, OpenAI Agents SDK, plus Claude Code internals) — then two independent proposal designers (mechanical-deletion lens vs. ownership lens), then an **adversarial verification** pass that re-opened every cited file, grep'd every consumer, opened the pinned `node_modules` SDKs, and ran git archaeology on contested claims. The verifier **rejected 1 proposal outright and corrected load-bearing factual errors in 13 of the 14 accepted ones** (wrong gate targets, false "strict superset" claims under CLI minification, a default-config value the proposal had wrong, a Google constructor that was already fixed). Those corrections are folded into the plan below; the rejection and the dropped sub-scopes are recorded as traps so they are not re-litigated.

## TL;DR — verdict

**TeXRA's error architecture is already right; the gains are coverage and ownership, not redesign.** The provider boundary independently converged on the industry's strongest idiom — `Symbol.for`-keyed metadata attached once at the SDK boundary (byte-for-byte Vercel's `vercel.ai.error` marker pattern), one 839-line normalization core (`sdkErrorUtils.ts`), `userRetryable` as data on a canonical Zod `ProviderError`. Do not restructure any of that.

The real diseases, all fixable by deletion or ownership transfer:

1. **Too many derivations of the same fact.** Abort-ness is derived five ways (one of which causes a real ghost-resume bug in the Responses background path); missing-API-key has two divergent string classifiers and one dead pattern; status-code extraction exists in three forms; two public entries exist for one normalization.
2. **No single retry owner.** The Anthropic/OpenAI SDK clients silently retry 2× under TeXRA's own node-level loop, and the OpenRouter SDK default will back off for **up to one hour** inside one visible attempt. `texra.model.retry.maxAttempts: 0` does not mean zero. (Google is already fixed — the in-repo precedent to copy.)
3. **Structure dies one seam above where it's computed.** `normalizeProviderError` caches a full `ProviderError` (statusCode, requestId, 4KB partial-text tail) on the thrown object; `RetryState` flattens it to `{message, userRetryable}`; the flows re-throw bare `new Error(message)`; the run boundary then string-sniffs the message it helped write. One failure renders up to 3 transcript rows + a toast in the extension, prints twice to CLI stderr, twice in the TUI transcript — and **desktop shows nothing and hangs forever in WAITING on retryable errors** (no `requestShowError` listener, retry affordance wired to `() => undefined`).
4. **The terminal outcome is not data.** Every studied agent SDK delivers run failures as typed result variants on the same union as successes (Claude Agent SDK `SDKResultMessage`, Vercel `fullStream` error/abort parts). TeXRA throws + side-channel-toasts. The fix is one `result` variant on the existing `AgentEvent` union — **hard-gated on SDK Step 7d**, paid for by deleting the lifecycle toast emitters.

**Honestly bounded:** only Tier 1 nets negative LOC (~−10 to −20 in src, plus tests), and it contains the two genuine bug fixes (abort-during-retrieve ghost-resume; desktop WAITING hang via the stage-1 decline). Tiers 2–3 net-ADD lines (+30 to +80 each) — consistent with this repo's measured lesson that cross-host unification adds text; the value is one canonical owner per concern and host parity, not line count. Every proposal below names its explicit deletions or ownership transfers; none adds a layer.

## Catch budget — target end-state (2026-07 addendum)

Seven planes may catch; everything else returns result types or lets errors crash to them. (1) **Host entry boundaries**: extension command handlers via `showLoggedErrorMessage`, CLI `bin/texra.ts` top level, desktop IPC handlers. (2) **The provider SDK boundary**: `withSdkErrorTag` → `normalizeProviderError`, classified once (Map 1's settled architecture). (3) **The tool boundary**: `invokeToolSafely` → one tool card back to the model (Map 2, stage e). (4) **The run-lifecycle terminal boundary**: `runFlowWithLifecycle`/`AgentRunLifecycle` with `classifyAgentError` decided once; the T3-2 result variant is this plane's data form. (5) **Listener fan-out isolation**: trace/hub subscriber guards so one consumer cannot kill its siblings. (6) **Resource cleanup**: `finally`, dispose-on-error, launch-saga compensation. (7) **ENOENT-predicate reads**: `isFileNotFoundError`-only defaults that rethrow everything else. A catch outside these planes must carry the review-checklist §15 L1–L5 classification in its PR, and a Zod `.catch(default)` on persisted data is never inside budget (loud reads, #6966 bullet 5). The 2026-07 audit measured 880 catch sites at ~87% within budget; the budget exists so the other 13% only shrinks — new masking catches are review blockers per checklist §15, and each cleanup item lands as an ownership transfer to one of the seven planes, consistent with this doc's one-owner-per-concern target.
