## How this was produced

A multi-agent workflow: four parallel read-only maps — (1) the nine process-global registries and their post-7a–c shape, with git archaeology on the landing commits; (2) every host resolve-side call site across extension/CLI/desktop, keyed-id matrix included; (3) the full run/trace lifecycle from `buildAgentLaunchContext` through `runFlowWithLifecycle`'s `finally`; (4) prior art on run/session handles and result events (Claude Agent SDK `Query`/`SDKResultMessage`, Vercel AI SDK `streamText`, OpenAI Agents `RunResultStreaming`, all from official docs). Then two independent designers — a minimal-composition lens and an SDK-surface lens — then an **adversarial verification** pass that re-opened every cited file and grep'd every consumer. Both designs came back **sound-with-corrections**; this document takes the minimal design's staging discipline (identity-wrapped default instance, behavior-neutral PRs, no new facade layer), grafts the SDK-surface design's verified end-state pieces (the session `hostChannel`, the desktop per-window session, the deferred per-run control handle), and folds in **all 19 binding verifier corrections** — including one false reachability claim in the result-variant outcome mapping, three missing call sites in the migration list, a usage-type mismatch, a layering-inversion trap in the flusher relocation, and a stale desktop citation.

## TL;DR — verdict

**7d is mostly wiring, and the staging can be byte-identical until the last two PRs.** The three landed classes already form a constructor-injectable dependency chain (`InterruptRegistry` → `ExecutionRegistry({interrupts, streamStatus})` → `RunCoordinatorBridge(registry)`), the per-run control handle already exists (`AgentExecutionHandle`, created and tracked in `runFlowWithLifecycle`), and the resolve side is already keyed by ids that round-trip through `show*` payloads. The `SessionHandle` is therefore a **thin composition record, not a facade**: it re-exposes no per-concern methods; callers keep the existing instance vocabulary (`session.coordinators.resolvePlanApproval(...)`, `session.executions.stopAgentStream(...)`) — exactly how 7a–c landed.

The genuinely new work, in order: (1) a `defaultSessionHandle` that wraps the existing module singletons **by identity** (zero call-site changes, single-session behavior byte-for-byte); (2) threading the session into the run via the frozen `RunContext` — the same ALS seam tools already use for `runtimeHost`; (3) hanging the sweeps (`cleanupAllRequests`, `retainOnly`, the flusher set) off the handle so a session's delete-all sweeps only its own streams; (4) hosts holding the handle at construction, with desktop's `DesktopProgressBridge` becoming the first true per-instance session and `SessionHandle.dispose()` becoming the **first production caller of `ExecutionRegistry.dispose()`** — retiring the audit-§15 subscription residue; (5) the T3-2 `result` variant, emitted at the `runFlowWithLifecycle` boundary and consumed by hosts through the session's hub — which is exactly why T3-2 is hard-gated on 7d: without the session there is no host channel for trace events (there is no `executionId → trace` registry, deliberately).

**PRs 1–5 are behavior-neutral. PRs 6 and 7 are the two behavior-changing cutovers** (the dual-emit release of the `result` variant, then the deletion of the three lifecycle toast emitters one release later). The milestone-13 bus re-route and the per-run control handle are named follow-ons, **not** minimal 7d.

**Honestly bounded (LOC lesson):** the 7d train is net-ADD — realized at roughly **+1,500 including tests** (about +930 of which is the new vitest suites; the ex-ante "+300 to +500" estimate undershot because the behavior-neutral PRs are test-locked far more heavily than they are code-changed), until the follow-on books the producer-shim deletions (~−60 to −100). The payoff claimed is ownership and isolation — a session's sweeps cannot touch another session, the §15 residue closes by construction, and T3-2 is unblocked — not line count. Do not let any PR in this train re-justify itself by LOC.

## Ground truth this plan is built on (supersedes stale framings)

These five corrections are load-bearing; earlier plan text and the standing-trap phrasing describe shapes that no longer exist. Cite this section, not the older text.

1. **There are no delegator functions.** The plan language "classes with delegators, zero call-site changes" did not survive contact: 7a (`9d7b9c434`), 7b (`94ead2298` + `14a2bd635`), and 7c (`0a927c689`) each deleted the free functions and migrated every call site to instance methods on the module-default singletons **in the same commit**, plus a cross-instance isolation vitest. That — one ownership concern per behavior-neutral commit, same-commit call-site migration, isolation test — is the staging pattern this plan copies. The `2026-05-30-agent-sdk-readiness.md` 7c status line ("resolve-side exports stay delegators; the cross-key ref-counting + three-way fallback preserved verbatim") is stale on both halves; PR 1 fixes it.
2. **The bridge mechanism to preserve verbatim is the current one, not the documented one.** `retryCoordinatorRefs` ref-counting and the three-way (request-map → runStreams → ambient ALS) fallback were collapsed on main (`0b210affe`, `5d9b81f32`, with tests). What is now load-bearing and must survive relocation unchanged: (a) resolve-by-id pure map lookups usable **outside** the run's ALS, returning `?? false`; (b) the identity-guarded retries finally-delete (`if (this.retries.get(streamId) === coordinators)`); (c) the indexed-requests-first, handle-resolved-coordinators-second clear order (`clearPlanApprovalForStream`'s `entries.length === 0` fallback; `clearRetryRequest`'s two-source `Set` union); (d) tolerance of handles with `coordinators === undefined` (the `src/tools/delegation/childStream.ts` construction). Do **not** "restore" the deleted ref-counting. The `clearAllProposals` asymmetry (no `activeCoordinators()` union, unlike its two siblings) is **preserved, not normalized** — changing sweep semantics inside a relocation PR forfeits behavior-neutrality.
3. **Desktop retry is a decline, not a stub.** Since `f0f690610` (T1-6/T1-7), `desktopAgentExecution.ts` wires `showRetryRequest: (payload) => { runCoordinatorBridge.cancelRetry(payload.streamId); }` ("Desktop has no retry panel yet: decline the affordance"). The conclusion stands — zero `triggerRetry` sites, T3-2's desktop result rendering is genuinely new plumbing — but PR 4c must rewire this one bridge resolve site through the session.
4. **Anchor on event names, not file names.** This tree still has `src/tools/odyssey/odysseyStore.ts` emitting `odysseyStateChanged`; the goal rename lives on unmerged side branches. All acceptance text and tests for the bus re-route key on the event names (`odysseyStateChanged`/`goalStateChanged`, `resolveExternalInquiry`, `inquiryThreadUpdated`). Re-grep at implementation time.
5. **The "7 registries" framing overcounts.** `toolInjectionRegistry` is
   composition-root feature configuration (registered once after `initPlatform`,
   no stream-keyed state, `throw` on duplicate registration). Per-session
   re-instantiation would lose registered features or hit the throw. It is
   **genuinely per-process** and stays off the handle. Earlier drafts also named
   an idle-continuation registry; that module has since been deleted and is not a
   live registry.

## The design

### The handle: one new type, zero new per-run types

`SessionHandle` (new file `src/agent/runtime/SessionHandle.ts` — the planned 7d name, kept to stop further name drift) is a composition record over the four landed runtime owners plus the flusher set and an optional session-scoped host channel. It is **not** a facade and **not** a conversation API (prior-art rule: Anthropic shipped and deleted exactly that — TS `createSession`, removed in Agent SDK 0.3.142; continuity stays in options + storage, which TeXRA already has via `ValidatedExecutionRequest`).

```ts
// src/agent/runtime/SessionHandle.ts
export class SessionHandle {
  readonly interrupts: InterruptRegistry;
  readonly executions: ExecutionRegistry; // ctor-owns ProcessOutputPoller + the status-subscription disposer
  readonly coordinators: RunCoordinatorBridge; // the resolve-side surface — relocated, never deleted
  readonly subscriptions: ExecutionSubscriptionBinder;
  readonly flushers: Set<() => void>; // T3-1(d): per-session activeFlushers
  readonly hostChannel?: AgentRuntimeHost; // session-scoped emit; the named non-run-scoped surface
  // for the 5 host-path tool emissions (follow-on F-1). Unset ⇒ those stay on the bus.

  constructor(
    init?: Partial<
      Pick<
        SessionHandle,
        | 'interrupts'
        | 'executions'
        | 'coordinators'
        | 'subscriptions'
        | 'flushers'
        | 'hostChannel'
      >
    >,
  );
  // Fresh-mode construction is in FORCED dependency order, every cross-reference explicit —
  // never letting a member default to a neighboring module singleton (the silent-state-split trap):
  //   interrupts    = new InterruptRegistry();
  //   executions    = new ExecutionRegistry({ interrupts, streamStatus: StreamStatusService });
  //   coordinators  = new RunCoordinatorBridge(executions);
  //   subscriptions = new ExecutionSubscriptionBinder({ registry: executions, releaseSource: ToolUseFollowUpQueue });

  flushPendingTraces(): void; // drains only this.flushers
  onResult(cb: (e: ResultEvent) => void): () => void; // PR 6: the host consumption channel for T3-2
  /** @internal */ attachRunTrace(trace: AgentTrace): () => void; // PR 6 hub seam — see attachment rule below

  dispose(): void;
  // Order: coordinators.cleanupAllRequests() → subscriptions.dispose() →
  //        executions.dispose()   ← FIRST production caller; retires the §15 status-subscription residue
  //        → interrupts.retainOnly(new Set())
  //          (InterruptRegistry has no clear(); retainOnly is the existing ProgressViewState precedent —
  //           verifier correction: do not invent a clear() unless PR 1 adds it explicitly)
}

export const defaultSessionHandle = new SessionHandle({
  interrupts: interruptRegistry,
  executions: executionRegistry,
  coordinators: runCoordinatorBridge,
  subscriptions: executionSubscriptionBinder,
  flushers: getActiveFlushers(), // exported accessor from @transcript/runTrace — see layering rule below
});
```

**Identity is the compatibility mechanism.** There is no delegator layer to preserve (ground truth #1), so the behavior-neutral seam is: `defaultSessionHandle`'s members **are** the existing exported singletons. Every unmigrated call site keeps hitting the same objects byte-for-byte for the entire train; migration is per-call-site `runCoordinatorBridge.x(...)` → `session.coordinators.x(...)` against the same instance. PR 1's tests assert the identities.

**Layering rule for the flushers (binding verifier correction):** `@transcript/runTrace.ts` cannot import `SessionHandle` — `src/agent/runtime` already imports `@transcript` (`AgentLaunchContext.ts`), and the reverse edge recreates the inversion the SDK plan's Step 2 removed. So `@transcript` exports the currently module-private `activeFlushers` set via an accessor (`getActiveFlushers()`); the default session **aliases** it; `createRunTrace` gains an optional `flushers` param defaulting to the module set. `flushPendingRunTraces()` survives as the process-level drain over **all** sessions' sets (the module keeps a registry of session flusher sets), preserving the shutdown contract for `ProgressViewState.flush()` and the CLI's `subscribeStreamLog`/`runChatTui` drains.

**The per-run handle already exists.** `AgentExecutionHandle` (`src/agent/runtime/ExecutionHandle.ts`) is the run-lifetime handle — executionId/streamId/category/runtimeHost/coordinators, status/elapsed/progress via the registry, interrupt via `stopAgentStream`/`kill`, live tool-use ops via `LiveToolUseFlowContext`. 7d composes; it does not rebuild. The `runAgent`-returns-a-control-handle item stays deferred (follow-on F-2), exactly as the plan says.

### Threading: the run reaches its session through `RunContext`

`RunAgentOptions`, `ExecuteAgentOptions`, **and** `ResumeToolUseFromSnapshotOptions` (all three — binding correction; the resume options bag has no session field today) gain optional `session?: SessionHandle` defaulting to `defaultSessionHandle`. `buildAgentLaunchContext` stores `ctx.session`; `withExecutionRunContext` copies it into the frozen ALS `RunContext` — the carrier the code already chose for `runtimeHost`/`coordinators`/`trace`. Field placement is coordinated with the DI doc's RunIdentity cohesion split, which churns the same files. Inside a run, tools and flows resolve via `tryUseRunContext()?.session ?? defaultSessionHandle` — no new parameters anywhere. `executeSubagent` launches children into the parent's session by the same read.

### Hosts

- **Extension** — one session per activation. `activate()` binds `defaultSessionHandle` and threads it as a ctor param to `ProgressViewProvider` → `ProgressViewMessageHandler`, `ProgressStreamLifecycleHost`, `SettingsViewMessageHandler`, and the command-registration closures (all verified constructible-with-a-handle at activate). Its eventual `hostChannel` is `extensionAgentRuntimeHost`, whose `emit` **is** `bus.emit` — so the follow-on re-route is observably identical on this host. `deactivate()` does not dispose the default session.
- **CLI** — one session per process, carried on `CliContext` as **`agentSession`** (binding correction: `runChatTui.tsx` already uses `session` pervasively for `TuiSessionState`; do not create the readability trap `context.session.executions.stopAgentStream(session.streamId)`). Headless `hostChannel` stays **unset** initially — byte-identical NDJSON; flipping it is the deliberate, release-noted decision in follow-on F-1.
- **Desktop** — `DesktopProgressBridge` is the proto-SessionHandle (its ctor already composes runtimeHost + resolve adapters + cleanup) and becomes the first true per-instance session: `createWindow` → `new SessionHandle()`; window close → `bridge.dispose()` → `session.dispose()`. The `hostChannel` is **not** wired now (it lands `new SessionHandle()`, not `{ hostChannel: this.runtimeHost }`): the field is a dormant F-1 seam with no readers in this train, and `this.runtimeHost` is built after the session field initializer anyway — the F-1 re-route moves session construction into the ctor body. The window-reopen orphan policy is made **explicit, not fixed**: runs launched by a closed window keep their dead `postToRenderer` closure (events dropped) — unchanged from today; rebind-or-orphan is its own future design if multi-window ships.

### Resolve side: relocate by identity, route by construction

UI callers run **outside** the run's ALS holding only ids minted inside runs and round-tripped through `show*` payloads (plan approval → `approvalId`; proposal → `proposalId`; retry/stop → `streamId`; kill/history-guards → `executionId`). The bridge's id→coordinator index relocates onto `session.coordinators` as the **same instance**, preserving ground-truth #2 verbatim. Resolve-site inventory, cited by method name (binding correction): extension `ProgressViewMessageHandler` has **7 bridge call expressions** (`cancelRetry`, `resolveProposal`, `triggerRetry` ×2, `resolvePlanApproval` ×3) plus `ProgressStreamLifecycleHost.clearRetryRequest`; CLI `approvalAdapter.dispatchApprovalDecision` + TUI `subscribeApprovals` dispatches; desktop IPC handlers + the `showRetryRequest` decline (ground truth #3).

**id→session routing with N sessions in-process: no process-level id index.** Each resolve adapter is constructed with its session, and the only place an id ever surfaces to a host is a `show*` event on that run's `runtimeHost` — wired by the launching host. The adapter that hears the request holds the right handle by construction. Cross-session resolves hit the wrong instance's map and return the existing `false` contract — safe, documented for SDK embedders ("resolve on the session that surfaced the request").

### The T3-2 `result` variant

```ts
// src/agent/trace/events.ts — extends StageStamp like every AgentEvent arm
export interface ResultEvent extends StageStamp {
  readonly type: 'result';
  readonly outcome: 'completed' | 'failed' | 'cancelled'; // cancelled is a SIBLING of failed (PRIOR-06 vitest lock)
  readonly executionId: string;
  readonly streamId: string;
  readonly agentName: string;
  readonly category: 'toolUse' | 'workflow';
  readonly isSubagent: boolean; // hosts preserve subagent toast suppression; orchestrator delivery
  // stays on onBeforeWaiting/FollowUpQueue — NOT rebased onto this event
  readonly error?: { kind: AgentErrorKind } & Partial<RetryErrorInfo>; // the T2-2 widened structured shape;
  // kind === 'missing-api-key' is what lets the extension keep its actionable SET_API_KEY buttons after deletion
  readonly usage?: RunUsageTotals; // CORRECTED TYPE — the accumulator's totals are RunUsageTotals
  // (totalInputTokens/totalOutputTokens/totalCost/…), NOT TokenUsageStats. Carried as-is; no lossy projection.
}
```

**Emission point — exactly two sites, both in `runFlowWithLifecycle`, both on `ctx.logger`, both strictly before the `finally`'s `ctx.disposeTrace()`.** Never from flows, `executeAgent`, `runAgent`, or the bus (the T3-1 review rule). The event is top-level **because lifecycle code never enters a `TraceEmitter` stage ALS scope** (`withStage`/`within`) — corrected mechanism; `parentStage.end()` pops nothing.

- **Success arm:** immediately after `ctx.parentStage.end(result.status)`, with `executionRegistry.untrack` **moved after the emission** (one-line reorder, covered by the exactly-once tests) so the registry's terminal `undefined` listener event never precedes the result event. Outcome mapping is **interrupt-aware** (binding correction — the "unreachable for root runs" claim was false): `runToolUseFlow`'s no-throw interrupt exit (`isInterrupted && !interruptedAfterDeliveredSubagentResult` → `EXECUTION_STATUS.INTERRUPTED`) reaches this arm with an ERROR-mapped status and **no** `lastError`; emitting `failed`/`error: undefined` for a user interrupt would break the cancelled-sibling lock on a reachable path. The success arm therefore maps: interrupt-produced terminal → `'cancelled'`; `END_GROUP_STATUS.ERROR` without interrupt → `'failed'` (kept as a defensive arm); otherwise `'completed'`. The no-throw-interrupt exit joins the test matrix.
- **Catch arm:** immediately after `ctx.parentStage.end(status)` / `streamStatus.set`, before the subagent/abort/throw three-way exit (one site covers all three; untrack already follows in each exit branch). Outcome = `classifyAgentError(err) === 'abort' ? 'cancelled' : 'failed'`, mirroring the existing STOPPED ≠ ERROR mapping.

**Hub attachment rule (binding correction):** the session's per-run subscriber is attached **after `buildAgentLaunchContext` returns** — not inside `assembleAgentLaunchContext` — with the detach disposer bundled into `ctx.disposeTrace`. This sidesteps the launch-failure compensation path entirely (`buildAgentLaunchContext`'s catch calls `runTrace?.dispose()` directly and the returned context never exists), and it **strengthens** the structural exclusion: the hub provably never observes launch-failing traces. The PR-6 leak test covers the launch-failure-after-trace-creation path, not just the lifecycle `finally`.

**Structural exclusions and locks:** launch failures cannot flow through the variant (trace disposed pre-handle; prior art unanimously throws pre-handle); the launch toasts and `suppressErrorNotification` keep their own single owner via T2-4. Resume funnels through the same boundary, so resumed runs emit for free; resume passes no lifecycle options, so resumed delegated runs emit as root (`isSubagent: false`) — **decided as the intended semantics** (it matches today's toast behavior) and test-locked so a future pass doesn't "fix" it into double delivery. Tool-use children deliver answers early via `onBeforeWaiting` and emit `result` much later (or `cancelled`) — the FollowUpQueue delivery is not rebased onto the event.

**Per-host consumption** rides `session.onResult` (fed by the hub subscriber) — the explicit seam the verifier demanded: extension toasts are bus-listener driven today and desktop consumes runtimeHost events, so "toast moves to the result consumer" means a **session-hub-driven consumer in host wiring**, mapping `error.kind === 'missing-api-key'` to the existing `INSTRUCTION_ACTION.SET_API_KEY` / `OPEN_CONFIGURATION_GUIDE` tokens in `agentEventListeners`. CLI headless: one ndjson `{kind:'result'}` record + one stderr line. Desktop: new explicit result rendering (nothing to piggyback on — ground truth #3). "One hub subscriber" is one session-owned subscriber **function** attached per run trace; per-run `TraceEmitter`s are created inside the run, so a literal single construction-time subscription is impossible.

## T3-1 acceptance-criteria coverage

**(a) One emission path for run-scoped events.** PR 2 makes the session reachable from inside every run (frozen `RunContext` field — the same ALS seam as `runtimeHost`) and PR 4 puts the handle in every host's hands: the two literal preconditions of "re-route only when the per-session handle exists." The re-route itself is F-1 — until then all 7 sites stay on the bus; the gate is **honored, not worked around**. The 5 host-path emissions get the named `hostChannel` surface (they fire outside any run; the run's runtimeHost is structurally unavailable to them), and the headless NDJSON contract change is an explicit release-noted decision. All criteria text and tests anchor on event names per the T3-1 cite rule.

**(b) Single-emission producers.** The hub **mechanism** lands in PR 6 (`attachRunTrace`: one session-owned subscriber function attached per run trace after the launch transaction commits, detached via `disposeTrace`); the **derivations** migrate in F-1 — `UsageMonitor`'s dual emit and the two conversation-progress emitters become single producer emissions with hub-derived secondary views, agentCategory-aware, preserving the intentional workflow-only transcript-stats copy (category-gate lock test). Producers are not pre-consolidated (divergent semantics; the measured net-ADD shape); the deletion LOC stays booked at the milestone.

**(c) Terminal result as data.** PRs 5–7 deliver T3-2 exactly as recorded: one discriminated arm on `AgentEvent`, emitted only at the `runFlowWithLifecycle` boundary (both arms, pre-`disposeTrace`, pre-untrack), `cancelled` a sibling of `failed` with the vitest lock **including the no-throw interrupt exit**, error carrying the T2-2 structured shape + `kind`, usage as `RunUsageTotals` from the PR-5 cache, launch failures structurally excluded and test-locked. The handle **is** what hosts consume it from (`session.onResult`) — satisfying "an acceptance criterion of the handle design," and demonstrating why T3-2 is hard-gated on 7d.

**(d) Flusher lifetime.** PR 3 moves `activeFlushers` onto the handle (per-session sets; `createRunTrace` takes the session's set, including `childStream.ts`'s non-lifecycle traces via the RunContext-carried session), while `flushPendingRunTraces()` survives as the process-level drain over all sessions' sets — the shutdown contract for `ProgressViewState.flush()` and the CLI callers is unchanged, and desktop's per-window flush routes through the injected session.

**Plus the §15 residue closure:** the `clearAll*` path becomes per-session by construction (a session bridge's `activeCoordinators()` enumerates only its own registry's handles; `cleanupAllApprovals` routes through the session), and `SessionHandle.dispose()` is the first production caller of `ExecutionRegistry.dispose()` — retiring the module-level `onDidChange` subscription for every non-default session, with the default session's process-lifetime subscription recorded as a deliberate single-session-host decision.

## Risks

1. **Concurrent churn.** PRs 2–3 touch the files the DI RunIdentity split and ongoing error-pipeline work churn (`RunContext`, `AgentLaunchContext`, `executeAgent`, the cycle nodes). One owner decision on the `RunContext.session` field placement; rebase immediately before merge; cite by clause text.
2. **Silent state split.** Neutrality of PRs 1–4 rests on identity-wrapping plus the explicit-cross-ref ctor rule — a fresh member defaulting to a neighboring singleton means cross-session interrupt leakage or cross-session `clearAll` sweeps. Mitigation: identity assertions + the fresh-ctor test + the PR-2/PR-4 isolation vitests.
3. **Incomplete migration = silent desktop breakage.** The per-window session only works if launch entries (`runAgent` dynamic import, resume), `sendFollowUp`, `desktopSettingsIpc` guards, and `ProgressViewState` flush all route through the session — otherwise resolves return `false` and sweeps no-op silently. PR 4c's round-trip test is the guard; grep-all-three-singletons is the checklist.
4. **NDJSON contract.** PR 6 adds a `result` record; F-1 may add tool-event records. Each is a deliberate, release-noted addition; the behavior-neutral PRs carry byte-parity tests so additions happen only where declared.
5. **Dual-emit double-presentation.** Staging discipline (extension consumer ships dark in PR 6) is process-enforced, not type-enforced — PR 6 includes the explicit not-registered test.
6. **Trace-hub leak is silent.** `TraceEmitter` swallows subscriber throws; the detach test (including the launch-failure path, made structural by the post-build attach rule) is the only guard.
7. **Success-arm interrupt mapping.** The no-throw interrupt exit is reachable; if the interrupt-aware mapping is dropped in review, a user interrupt emits `failed`/`error: undefined`. The PR-6 test matrix pins it.
8. **T2-2 and PR 5 are hard prerequisites.** Without the structured `lastError` attach, the `error` field is a type lie; without `lastTotals()`, usage ships `undefined` everywhere and PRIOR-09 silently dies. Do not land PR 6 with fallbacks.
9. **Documented residues are real cross-session leaks until addressed:** the requestId-keyed approval controllers swept globally by `cleanupAllApprovals`' non-bridge half; the per-session binder wired to the shared `ToolUseFollowUpQueue`; desktop window-reopen orphaning live runs' runtimeHost. Minimal 7d makes these explicit, not fixed.
10. **Exhaustive-switch breakage** for SDK consumers on the PR-6 upgrade (compile-time only) — release note.
11. **odyssey→goal rename in flight** invalidates file-name cites for 4 of the 7 bus.emit sites — event-name anchoring everywhere; re-grep at implementation time.
12. **LOC honesty.** The train is net-ADD until F-1 books the producer deletions. The payoff is ownership/isolation + T3-2 unblocked; reviewers should reject any PR in this train that sells itself as simplification.
