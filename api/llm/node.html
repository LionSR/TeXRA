@texra-ai/llm/node ​

Node.js entry of @texra-ai/llm: binding a catalog model to its wire protocol (bindModel) and running subscription OAuth sign-in flows.

Guide: Read Model Layer (@texra-ai/llm) for a complete selectModel $\to$ bindModel $\to$ prepareTurn $\to$ streamTurn example.

Key exports by role ​

  • Protocol binding: bindModel, BindSpec, Binding, and ModelCredential dynamically load only the requested protocol (anthropic-messages, openai-responses, google-interactions), manage scoped connections and file uploads in the caller's Scope, and classify provider failures into ModelError.
  • Subscription sign-in (codex, xai): ChatGPT (codexCoordinator, codexLoginWithLoopback, codexLoginWithDeviceCode) and Grok (xaiCoordinator, xaiLoginWithLoopback, xaiLoginWithDeviceCode) OAuth flows, plus SharedAttempt for coalescing concurrent refreshes.

Binding ​

A bound model and the facts its configuration fixed.

ts
interface Binding {
  readonly model: Model;
  readonly origin: ModelOrigin;
  /**
   * The config the model runs and bills with on its route: its window, its
   * prices, and the media its route carries (`capabilities`).
   */
  readonly config: ModelConfig;
  /** The route the binding bills through. */
  readonly billing: BillingRoute;
  /** The output limit a turn takes unless it asks for less; null where the route takes none. */
  readonly maxOutputTokens: number | null;
  /** Turns can run as background work (submit and observe). */
  readonly background: boolean;
  /** One connection a failed turn invalidates (the Responses WebSocket). */
  readonly persistentConnection: boolean;
  readonly serviceTier: 'fast' | null;
  /** The route takes a tool choice naming one function. */
  readonly forcedToolChoice: boolean;
}

bindModel ​

Bind one model. The vendor rules and the failure verdicts load on demand, like the protocol modules. The connection, and the files the model uploads, live in the caller's scope: an upload the provider will not confirm deleted is logged and left to its own expiry.

ts
const bindModel: (spec: BindSpec) => Effect<Binding, ModelError, Scope>

BindSpec ​

One model on one decided route, and what the caller asks of it. The protocol is the model's provider's, and the route fixes the config it runs (routeConfig), the credential scope stamped on its origin and the plan it bills.

ts
interface BindSpec {
  /** The llm-zoo entry, before its route's overrides. */
  readonly model: ModelConfig;
  readonly route: Extract<
    ModelRoute,
    { kind: 'api-key' | 'chatgpt-subscription' | 'xai-subscription' }
  >;
  readonly endpoint: string;
  readonly credential: ModelCredential;
  /** Each option has a default; the booleans default to `false`. */
  readonly options?: {
    /** The output ceiling, before the model's own rules; the catalog's by default. */
    readonly maxOutputTokens?: number;
    /** The sampling temperature where the model takes one; the provider's own by default. */
    readonly temperature?: number;
    /** The model's default reasoning (`chooseReasoning`) unless given. */
    readonly reasoning?: ReasoningChoice;
    readonly parallelToolCalls?: boolean;
    /** GPT-5 sends a reasoning summary only when asked. */
    readonly reasoningSummary?: boolean;
    /** Google keeps the conversation server-side. */
    readonly serverState?: boolean;
    /** OpenAI's fast service tier, where the model offers it. */
    readonly fastTier?: boolean;
    /** The caller would serve Responses over its WebSocket. */
    readonly webSocket?: boolean;
    /** The caller would deliver turns as background work; it wins over the socket. */
    readonly background?: boolean;
    /** The fetch every HTTP request goes through. */
    readonly fetch?: typeof fetch;
  };
}

LoopbackLoginOptions ​

What a provider's loopback sign-in takes from its host.

ts
interface LoopbackLoginOptions<S extends SubscriptionSession> {
  /**
   * The coordinator that builds the authorize URL and exchanges the code.
   * The exchange is a program, so it runs on this flow's own fiber:
   * interrupting the login reaches the token exchange and the session store.
   */
  readonly coordinator: Pick<
    SubscriptionCoordinator<S>,
    'buildAuthorizeRequest' | 'loginWithCode'
  >;
  /**
   * Show (and normally open) the consent URL. A program, so the host's own
   * presentation runs on this flow's fibers and its failure — typically a
   * {@link LoopbackTransportUnavailableError} — reaches the caller through
   * the error channel instead of a rejection this flow has to re-wrap.
   */
  readonly openBrowser: (url: string) => Effect.Effect<void, Error>;
}

LoopbackTransportUnavailableError ​

The loopback route could never be established — the registered callback port(s) could not be bound, or the host could not reach a browser at all. Distinct from every other sign-in failure because nothing was asked of the user yet: a host with a device-code transport can retry on that instead.

ts
class LoopbackTransportUnavailableError extends Schema.TaggedError<LoopbackTransportUnavailableError>()(
  'LoopbackTransportUnavailableError',
  { message: Schema.String, cause: Schema.optional(Schema.Defect()) },
)

ts
type ModelCredential =
  | { readonly kind: 'api-key'; readonly apiKey: string }
  | {
      readonly kind: 'codex';
      readonly accessToken: string;
      readonly accountId: string | null;
    };

SharedAttempt ​

Single-flight for an Effect program: concurrent callers of {@link run} share one attempt of the work, and each caller's interruption abandons only its own wait.

The work runs on a detached fiber, never on the first caller's. Were it run on the caller's fiber, stopping that caller would interrupt the attempt every joiner is waiting on, and an interrupt landing mid-work (after a provider rotated a single-use refresh token, before it was stored) would drop the result nobody else can recreate. A detached attempt with no caller left still completes, and no caller's interrupt can end it, so the work must carry its own deadline: a stalled attempt holds the slot, and every caller joining it, until the work gives up by itself.

The check, the claim and the fork run under one uninterruptible mask and share one synchronous segment, so a second caller can never mint a second attempt and an interrupt can never land between claiming the slot and starting the fiber that finishes it.

ts
class SharedAttempt<A, E>

SubscriptionCoordinator ​

One provider's subscription session over the caller's secret store: reading it, keeping it fresh, signing in and out. The mutating and refreshing programs fail with {@link SubscriptionOAuthError}, or with the secret store's own {@link SecretsFailed} when it rejects.

ts
interface SubscriptionCoordinator<S extends SubscriptionSession> {
  /** The stored session, or null when none is stored; a stored one that
   *  does not parse fails `fatal`. */
  loadSession(): Effect.Effect<
    S | null,
    SecretsFailed | SubscriptionOAuthError
  >;
  /** Signed-in status of the stored session. */
  getStatus(): Effect.Effect<
    SubscriptionSessionStatus,
    SecretsFailed | SubscriptionOAuthError
  >;
  /** The stored session, refreshed when it expires soon. */
  getFreshSession(): Effect.Effect<S, Error, HttpClient.HttpClient>;
  /** Refresh now, while the stored session still holds `accessToken`: the
   *  provider rejected it before its expiry. */
  refreshRejected(
    accessToken: string,
  ): Effect.Effect<void, Error, HttpClient.HttpClient>;
  /** Forget the stored session. */
  signOut(): Effect.Effect<void, SecretsFailed>;
  /** The PKCE authorize URL for a loopback callback on `port`. */
  buildAuthorizeRequest(port: number): SubscriptionAuthorizeRequest;
  /** Exchange an authorization code and store the session it grants. */
  loginWithCode(params: {
    code: string;
    verifier: string;
    redirectUri: string;
  }): Effect.Effect<S, Error, HttpClient.HttpClient>;
  /** Store the session a completed token grant returned. */
  storeTokens(tokens: SubscriptionTokenResponse): Effect.Effect<S, Error>;
}
